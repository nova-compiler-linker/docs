## 3. 演进与冲突

### 3.1 `float` 的宽度：旧记录已作废 `已答`

| 版本 | 说法 | 出处 |
|---|---|---|
| 旧（**作废**） | `float` 直接 16 位，不分 `double` | 01 笔记 §1.4「演进过程」；01 §9 微信确认 |
| **定稿** | **`float` = 8 字节，IEEE754 存储** | 本节课速记 + 课后确认 |

**课后确认原话**：8 字节 IEEE754，旧的「16 位」**作废**。

处理结果：
- 规范 `nova-spec.md` §1.5 / §2.6 均按 **8 字节** 记录
- 规范 §9.4（新旧冲突项）**已销掉**
- 01 笔记 §1.4 的「直接 16 位」已加**作废标注**，避免两处打架

### 3.2 `array` 归结为 `class`：结构变化

- 旧：`array` 与 `bool`/`char`/`int`/`float`/`string` **并列**在基础类型集合里（01 笔记 §1.5、规范 §2.1、§3.1）
- 新：**`array` 归结为类类型** → 规范 §2.1 已补「值类型 / 类类型」两分类，§3.1 已注明
- 连带影响：
  - **传递语义**：数组本来就「传引用」（规范 §2.3），与类类型传引用**口径一致**，此处不冲突，反而更自洽
  - **数组大小**：既归为 class，`byte` 就按「视成员数量」走 —— 但「维度 / 长度」算**类型信息**还是**隐藏成员**，未定（见 §4）
  - **对齐**：`array` 的对齐 = 最大成员的对齐 = **元素类型的对齐**（`array[int | 9]` → 4）

### 3.3 一条可以观察到的规律（仅记录，未拍板）

本次给出的值里，除 `void`（0/1）与 `class`（视成员）外，**`alignment` 恰好等于 `byte`**：
`bool 1/1`、`char 1/1`、`int 4/4`、`float 8/8`。
这与规范 §2.2「**默认对齐**」相容，但**是否升格为通例**（`alignment = 自身 byte`）尚未明确 → 见 §4 第 3 条。

## 4. 本次新增的待确认清单 `?`

> 全部同步登记在规范 §9.2。**我不替你拍板。**

**A. 类型细节表本身的缺口**

1. **`string` 的 byte / alignment / operation** —— 表里没给；且它属于**类类型**还是另设的特殊内置类型？
2. **对齐是否成通例** —— 所有值类型一律 `alignment = byte`，还是每类型单独拍？
3. **`bool` 的取值表示** —— 1 字节里存 0/1？比较结果是否也是 0/1？
4. **`void` 的 alignment = 1 的用途** —— 既然 0 字节，这个 1 是给什么用的（数组基类？指针目标？函数返回？）

**B. 运算列（operation）的语义边界**

5. **「混合运算」的确切含义** —— 是 `int` 与 `float` 可混合参与算术、隐式提升为 `float`？提升方向与结果类型是什么？
6. **`char` 的「整型运算」范围** —— 是否含与 `int` 混合、是否自动提升为 `int`？`'a' + 1` 结果是什么类型？
7. **运算列的粒度** —— 只记算术 / 关系，还是也覆盖「能否赋值、能否作返回值、能否取 `&`、能否作数组基类」？

**C. 类布局（影响 ABI 与 `nvld`）**

8. **`none` 的存储方式** —— 你留的疑问。至少三种可选路子（仅列举取舍，不拍板）：
   - (a) **编译期常量，不占存储**：`void` 是真·空类型，`none` 只出现在类型/返回语境，运行时无表示 —— 最省，但「一切皆表达式」下 `let x = f();`（`f` 返回 `void`）没地方放值
   - (b) **零字节对象，有地址不可解引用**：与 `void` byte=0 自洽，能取地址、能当占位
   - (c) **单字节哨兵值**：与 `void` 的 byte=0 **冲突**（要改表）
9. **方法表 / vptr** —— 有 `override` 与 `<-` 继承，动态分派怎么做？若用 vptr，它**算不算进「视成员数量」**？放在对象头部还是尾部？（直接影响二进制兼容）
10. **成员排布顺序** —— 按声明顺序？还是允许编译器重排（C++ 的自由度）？对齐填充规则是什么？
11. **继承时的布局** —— `class tiger <- public felid`：基类子对象放**最前**还是别处？多重继承若要做（规范 §9.1 第 3 条未定），大小与对齐怎么算？
12. **`array` 的大小怎么算** —— `array[int | 9]` 的 byte 是 `9 × 4 = 36`？长度/维度存在**类型里**还是**对象头里**？若归为 class，「视成员数量」具体指哪些成员？

## 6. 类型接口：`array` 与 `string`

### 6.1 原始速记（逐字保留）

```
array:
    attributes:
    - length
    - internal_storage
    operations:
    - length(): int
    - [index]: reference

string:
    attributes:
    - length
    - internal_storage
    operations:
    - length(): int
    - [index]: reference
    - [n:m]: &string

在语法规范里搞单另的yaml 存各种类型的接口这个 vector等reserve 先不写
```

### 6.2 结论表 `已定`

| 类类型 | attributes | operations |
|---|---|---|
| `array` | `length`、`internal_storage` | `length() -> int`、`[index] -> reference` |
| `string` | `length`、`internal_storage` | `length() -> int`、`[index] -> reference`、`[n:m] -> &string` |

要点：

- 两个类型的**属性结构相同**（`length` + `internal_storage`），差别只在 `string` 多一个**切片**操作
- `[index]` 返回**引用** —— 与 §2.4「引用是别名，一个单元的不同名字」一致，意味着 `a[0] = 1;` 改的是底层存储本身
- `[n:m]` 只给了 `string`，返回 **`&string`**（不是副本），**左闭右开**（§5.3）；`array` 有没有待确认
- 同一类型上既有 `length` **属性**又有 `length()` **方法**，两者关系未定

### 6.3 落地：`nova-types.yaml`（按你的要求新建）

类型接口单独放结构化文件 `nova语法规范/nova-types.yaml`，**只存你给的这两个类型，别的一个不写**：

```yaml
array:
    attributes:
    - length
    - internal_storage
    operations:
    - "length(): int"
    - "[index]: reference"

string:
    attributes:
    - length
    - internal_storage
    operations:
    - "length(): int"
    - "[index]: reference"
    - "[n:m]: &string"
```

**演进（我搞错又被纠正的地方，记一笔）**：第一版我自作主张把 8 个类型全写进去了，还加了 `status` / `kind` / `byte` / `deferred` / `undecided` 一堆字段 —— **已全部删除**。你的要求是：**只存接口、其他类型别写、`vector` / `reserve` 先不写**。

**`operations` 为什么带引号** `已答`：

- 原样的 `- [n:m]: &string` **YAML 直接语法错误**（Psych: `found unexpected ':' while scanning a plain scalar`）
- 而且不统一：`- length(): int` 会被解析成映射 `{"length()" => "int"}`，`- [index]: reference` 解析成**复杂键**映射 `{["index"] => "reference"}`（部分语言的 YAML 库会直接拒收）
- **你确认：全部加引号，统一成字符串列表** → 现在 `attributes` 与 `operations` 的元素**全是 `String`**，Ruby YAML 解析验证通过
