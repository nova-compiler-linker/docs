## 3. 逐条详述

> **阅读须知（2026-09-24）**：本节是**初稿（v0.1）的设计记录**，保留当时的理由与业界对照，供追溯。其中被跨章节协调推翻的条目以 **§2A 对账表**为准——凡 §2A 标"推翻/修订"的行，本节对应小节的"新定义"已不是现行规则，现行规则以规范正文 v0.2 为准。词法组（D-01…D-11）与"维持不变"清单中的条目，本节详述仍然有效。

### 第一组：词法（D-01 … D-11）

#### D-01 翻译阶段与最长匹配消歧

- **前状态**：规范完全没有翻译阶段的概念；`<>` vs `<`+`>`、`=>` vs `=`+`>`、`::` vs `:`+`:` 的消歧从未讨论。
- **新定义**：四阶段翻译（换行归一 → 注释替换 → token 化 → 语法分析）；token 化采用**最长匹配**（maximal munch）。
- **理由**：最长匹配是 C、C++、Java、Rust、Python 等所有主流语言词法分析器的共同基础规则，不采用则需要为每对歧义前缀单独定规则（Pascal 式），代价高且反直觉。`<>` 作为不等号正是 Pascal 遗产，与最长匹配天然兼容（`a<b>` 这种写法在 Nova 中无歧义场景）。
- **业界对照**：C++ [lex.pptoken]、Rust Reference «The Rust lexer matches the longest possible token»。

#### D-02 换行归一与注释替换为空格

- **前状态**：§1.3 定了 `#` 注释，但未说注释「变成什么」；换行序列（`\r\n`）未提。
- **新定义**：换行序列等价；注释替换为**一个空格**。
- **理由**：「注释=空格」保证 `1 #x\n 2` 不会被切成 `12`（若注释替换为空则产生 token 粘连事故）；换行归一是 Windows/Unix 源码互操作的必要前提。
- **业界对照**：C++ [lex.phases] 阶段 3（注释替换为空格字符）。

#### D-03 界符 token 集

- **前状态**：§1.6 只列「运算符」，`;` `,` `{}` `()` `[]` `:` `::` `=>` `<-` `|` `->` `.` `&` 散落在示例中，词法层从未登记。
- **新定义**：2.4.7 显式列出 operator / delimiter 两类，并说明 `&`、`|`、`<-`、`=>`、`->` 的专用语境。
- **理由**：词法章的完备性要求 token 全集可枚举；`&` 与 `|` 被引用/数组类型占用后**不再是运算符**，这一点必须白纸黑字，否则实现者会按 C 习惯加位运算。
- **业界对照**：C++ [lex.delim] 单独列界符表。

#### D-04 运算符优先级与结合性表

- **前状态**：§1.6 只给出运算符集合；`a and b or c`、`-a * b`、`a = b + c` 的解析从未定义。**这是第 2 章最大的空白**——没有优先级表，表达式 EBNF 无法成立。
- **新定义**：10 级优先级（后缀 > 一元 > 乘 > 加 > 关系 > 相等 > `and` > `xor` > `or` > 赋值），同级左结合、赋值右结合。
- **理由**：
  - 算术与关系层级直接沿用 C 传统，教学语言偏离 C 的收益为零、困惑成本极高；
  - `and` > `xor` > `or` 的顺序是布尔代数的运算强度顺序（与 C 的 `&&` > `^` > `||` 一致），Python 亦为 `not > and > or`；
  - `not` 取一元级（同 `!`），故 `not a and b` = `(not a) and b`——与直觉「先取非再相与」一致；
  - 赋值最低且右结合，配合「赋值值为 `void`」自然禁止级联赋值（规范 §4.1 已定），无需额外文法限制。
- **业界对照**：C++ [expr]、Python 3 Reference、Rust Reference（`*` > `+` > `as` > `==` > `&&` > `||` > `=`）。

#### D-05 `type()` 元记法具体化为 `T(expr)`

- **前状态**：§1.6 写「`type()` 为类型转换」。这既可读作「存在名为 type 的转换函数」，也可读作「type 是占位符」。
- **新定义**：`type` 是占位符；转换写作 `int(x)`、`float(c)` 等**调用形式**。
- **理由**：`type` 已是关键字（类型别名，§1.4），不可能同时是转换函数名；调用形式与构造函数调用 `point(1.2, 3.4)`（`point.nova:27`）语法统一，文法零成本。
- **业界对照**：Rust `as`、Go `T(x)`、C++ 函数式转换 `T(x)`——Go 与 C++ 的调用形式与 Nova 的构造语法最兼容。

#### D-06 整数字面量进制与分隔符

- **前状态**：§1.5 只有 `123`。
- **新定义**：十进制、`0x` 十六进制、`0b` 二进制；数字间 `_` 分隔；**无八进制、无后缀**；超 `int` 范围为错误。
- **理由**：八进制是 C 的历史包袱（`010` 歧义），Rust/Python3/Go 均已移除或改造；无后缀与「单一无符号性」（D-27）一致——语言里根本没有 `unsigned` 类型，后缀无的放矢；`_` 分隔符零解析成本（词法规则一行）且显著提升可读性。
- **业界对照**：Rust（`0x`/`0b`/`0o`/`_`，Nova 去掉 `0o`）、Go（`0x`/`0b`/`0o`/下划线不支持）、Python3（`0x`/`0b`/`0o`，无后缀）。

#### D-07 浮点字面量语法

- **前状态**：§1.5 只有 `1.5`；`eqroot.nova` 用了 `0.0`。
- **新定义**：小数点形式、指数形式（`e`/`E`，可带符号）、`.5` 与 `1.` 合法；一律 `float`（binary64）。
- **理由**：IEEE 754 存储已定（§2.6），字面量语法若缺指数则无法书写科学计数，`1e10` 是工程刚需；`.5`/`1.` 的合法性代价是词法上 `.` 的消歧（`.5` 与成员访问 `a.b` 不冲突——成员访问的 `.` 前必有标识符/`]`/`)`，最长匹配+上下文可判），收益大于成本。
- **业界对照**：C++/Python/Rust 全部支持 `.5`、`1.`、`1e10`。

#### D-08 `char` 值域与转义表

- **前状态**：§1.5 只有 `'a'`；`char` 1 字节已定但值域未定。
- **新定义**：ASCII 0–127；转义 `\n \r \t \\ \' \0`；非 ASCII 字面量非法。
- **理由**：1 字节 + 字符集 ASCII（§1.1）已把值域锁死在 0–255；取 0–127 而非 0–255，是为了让 `char` 与「提升为 `int` 后非负」兼容（D-29），且 7 位 ASCII 是 C 教学语言的惯例。完整转义表是词法章的完备性要求。
- **业界对照**：C++（`char` 实现定义符号性——Nova 不学，见 D-27）、Rust `u8` 式「无隐式符号歧义」。

#### D-09 字符串：UTF-8 字节序列、转义、不自动拼接

- **前状态**：§1.5 只有 `"a"`；编码从未讨论，但 `string` 的 `[index]` 返回引用（`nova-types.yaml`）使「索引的单位是什么」成为必须回答的问题。
- **新定义**：字符串是**字节序列**，源文本按 UTF-8 存入；转义同 char 加 `\"`；相邻字面量**不**自动拼接。
- **理由**：
  - 字节序列模型（Go `[]byte` 思想 + Rust `String` 的 UTF-8 约定折中）让 `[index] -> &char` 语义清晰（索引第 i 字节）；若按「字符」索引则需变长解码，与「`[index]` 返回引用（O(1) 别名）」冲突——引用必须指向稳定存储，UTF-8 变长字符无法用单字节 `char` 引用表示；
  - 不自动拼接：C 的相邻拼接依赖预处理阶段，Nova 无预处理器；静默拼接还会掩盖「逗号写漏」这类高频错误（Python 的 `"a" "b"` 拼接就常被 lint 警告）。
- **业界对照**：Go（字符串=字节序列，不可变）、Rust（UTF-8 但索引非法——Nova 取 Go 的简单性）。

#### D-10 数组字面量文法

- **前状态**：§1.5 只有 `[1, 2, 3]`。
- **新定义**：允许尾逗号；`[]` 仅上下文可判型时使用；元素类型统一（提升后）。
- **理由**：尾逗号是工程惯例（逐行 diff 友好）；元素类型统一是「长度是类型一部分」的必然推论——异构数组需要运行时标签类型，与强类型静态布局（§2.2）冲突。
- **业界对照**：Rust `[1, 2, 3]`（同型）、Go 复合字面量（尾逗号强制——Nova 取「允许」的宽松版）。

#### D-11 shebang

- **前状态**：无。
- **新定义**：首行 `#!/` 开头则整行忽略。
- **理由**：`#` 已是注释符，`#!/usr/bin/env nvc` 天然就是注释——**本条几乎是免费的**，写明只为消除「`#!` 是否特殊」的疑虑。严格说 D-11 不是新增语义，只是显式确认既有词法规则的推论。
- **业界对照**：Python、Perl、Shell 通用。

### 第二组：错误与初始化模型（D-12 … D-13）

#### D-12 运行时错误 trap 模型

- **前状态**：§9.2 第 8 条：「`[index]` 越界怎么办——Nova 无异常处理，越界怎么办」，且笔记明确此条「会直接卡住 nvc 的代码生成」。
- **新定义**：越界、除零、`int(f)` 越界、悬垂引用、栈耗尽 → **trap**（立即终止、非零退出码、无清理）；`int` 溢出 → 回绕（D-27）。
- **理由**：无异常语言只有三条路：
  1. **UB**（C 式）——违背「强类型 + 教学」定位，且与引用返回语义叠加后无法调试；
  2. **可选返回**（Rust `Option`）——Nova 无泛型、无枚举，造不出 `Option`；
  3. **trap/panic**（Java `ArrayIndexOutOfBoundsException` 的退化版、Go `panic` 的无 recover 版）——唯一与现有类型系统自洽的方案。
  实现代价：每次索引一条边界比较指令，与 Java/C# 同级；教学代价：零（行为可预期、可复现）。
- **业界对照**：Java（越界抛异常，Nova 去掉可恢复性）、Go（`panic`，Nova 去掉 `recover`）、Rust（release 模式 UB——Nova 拒绝之）。

#### D-13 未初始化变量零值

- **前状态**：§9.1 第 6 条 `?`；`point.nova:14`（`let s: string;`）、`hanoi.nova:13`（`let n: int;`）已在依赖一个未定义的默认值。
- **新定义**：`let x: T;` 合法，`x` 获得类型 `T` 的**零值**（false / 0 / 0.0 / '\0' / "" / 零元素数组 / 零值字段对象）。
- **理由**：
  - 示例已经在这么用了，不定义等于放任实现分歧；
  - 零值方案（Java/Go/C# 路线）保证「读取任何已声明变量永远有定义」，把未初始化 UB 从语言里彻底删除，与 D-12 的 trap 哲学同向；
  - 备选「强制初始化」（Rust 路线）会直接判 `point.nova:14` 非法，与示例冲突——示例是规范的证据，不能反过来改示例来迁就一个未定项。
- **业界对照**：Java（字段与局部变量的默认值规则）、Go（零值即好值）、Rust（拒绝默认值、走编译期 definite assignment 检查——Nova 不采，理由如上）。

### 第三组：类型与声明（D-14 … D-16、D-26 … D-34、D-47 … D-50）

#### D-14 `const &T` 与 `&T const`

- **前状态**：§2.4 表格两格「? 待补」；课堂已确认「位置有意义、都合法」，但各自含义未展开。
- **新定义**：`const` 在 `&` **前**修饰**被引用对象**（只读视图）；在 `&` **后**修饰**绑定本身**（Nova 中引用本无重绑定语法，故与 `&T` 等价、仅作自我文档用）。
- **理由**：这是 C++ 顶层/底层 const（top-level / bottom-level）规则的直接移植——`const int&` vs `int& const` 的区分是 C++ 教学的标准内容，课堂「位置有意义」的表述与之高度同构，几乎可以肯定教师心智模型即如此。示例 `print_arr(a: const &array)`（sort.nova:21）的用法（只读遍历）也完全吻合「const 在前=对象只读」。
- **业界对照**：C++ [dcl.ref]；Kotlin `val`/`var` 不区分此二者（Nova 跟 C++ 不跟 Kotlin，因为 Nova 有显式引用类型）。

#### D-15 多重赋值

- **前状态**：§9.1 第 4 条 `?`；`gcd.nova:3`、`sort.nova:16` 在用。
- **新定义**：左右个数必须相等；先求全部左值地址、再求全部右值、最后写入；类型为 `void`。
- **理由**：「先取址后取值」使 `a, b = b, a` 正确交换，这是交换惯用法的全部动机；不引入元组类型（D-44）则多重赋值必须有自己的文法产生式。
- **业界对照**：Python（右侧先构成元组再解包——语义等价，Nova 无元组故用「先取址」表述）、Go（`a, b = b, a` 单遍求值）、Swift（显式规定先求左值再求右值）。

#### D-16 `let` 推导规则

- **前状态**：§2.1「强类型 + 有限自动推导，占位符 `let`」；`eqroot.nova:4`（`let a = 0.0;`）在用，边界未定。
- **新定义**：有标注查标注；无标注从初始化表达式**完全推导**（含函数返回值、块值、数组字面量）；`let x: T;` 零值；`let x;` 非法；推导不跨语句。
- **理由**：「从初始化表达式取类型」是规则的最小闭包，`let a = 0.0` → `float`、`let d = math::sqrt(...)` → `float` 全部覆盖；「不跨语句」排除全局推断引擎（Hindley-Milner），与「有限」二字吻合，也与 Go `:=` 的局部性一致。
- **业界对照**：Go `:=`、Rust `let`（均局部推导）、C++ `auto`（初始化器必需——Nova 同）。

#### D-26 `void`/`none` 运行时表示

- **前状态**：§9.2 第 1 条，教师原话「留个疑问」。
- **新定义**：`none` **无运行时表示**（编译期占位值）；`void` 表达式**不可**绑定 `let`、不可作实参/操作数。
- **理由**：这是三种候选（§9.2 第 1 条自己列的 a/b/c）中的 (a)「编译期常量不占存储」路线。关键论据：`void` byte=0 已定（§2.6），(b) 零字节对象有地址会引入「0 字节对象的地址算术」这一 C++ 都嫌麻烦的规则，(c) 单字节哨兵直接推翻 byte=0。而「void 不可绑定」把「一切皆表达式」的例外压缩到一条规则：表达式有值 ⇔ 其类型非 void。Rust 的 `()` 是 1 字节可绑定的单元类型——Nova 的 `void` 更严格，因为 Nova 的 `none` 语义定位是「无值」而非「单元值」。
- **代价声明**：`let x = f();`（f 返回 void）非法意味着**副作用函数不能参与任何以值为中心的惯用法**（如 `let _ = f();` 也不允许）——教学语言可接受，登记备查。

#### D-27 `int` 二补数 + 回绕

- **前状态**：§2.6 定了 4 字节，signedness 与溢出行为未定。
- **新定义**：signed 二补数，$-2^{31} \le v \le 2^{31}-1$，溢出按 $\operatorname{wrap}_{32}$ 回绕，**非** UB。
- **理由**：二补数在 2020 年代已无争议（C++20 起强制、Rust/Java/Go 全用）；不引入 unsigned——一个 `int` 走天下的教学语言加无符号类型只制造 `a < -1` 恒假这类陷阱；回绕而非 trap 的理由：回绕是 ALU 的自然行为（零检查成本），且 `gcd`/`sort`/`hanoi` 等示例程序无一依赖溢出检测；需要饱和/检测时由 `math` 包提供函数（显式优于隐式）。
- **业界对照**：Java（回绕）、Go（回绕）、Rust（debug trap / release 回绕——Nova 不学这种「模式分裂」，行为必须唯一）。

#### D-28 整除截断向零 + 余数恒等式

- **前状态**：`/` `%` 存在（§1.6），语义未定。
- **新定义**：`a/b` 向零截断；`a % b` 符号随 `a`；恒等式 $a = (a/b) \cdot b + a \% b$ 成立。
- **理由**：向零截断是 C99 之后几乎所有硬件与语言的共识（x86 `idiv` 原生行为）；Python 的地板除（`-7 // 2 == -4`）对教学者直觉更友好但实现成本高（需要额外调整序列），且 `gcd.nova` 的 `%` 用法（欧几里得算法，操作数恒正）在两种方案下等价——无示例证据支持偏离共识。
- **业界对照**：C99、Java、Go、Rust（全部向零）。

#### D-29 / D-31 隐式提升链与混合运算

- **前状态**：§2.6 表写了「混合运算」四个字；§9.2 第 11、12 条 `?`。
- **新定义**：`char → int → float` 单向提升；二元运算取提升链上最窄公共类型；`bool` 不参与任何算术；`char op char → int`。
- **理由**：`char→int` 提升（integer promotion）是 C 传统且硬件友好（寄存器宽度）；`int→float` 单向是数值语义的自然包含关系；拒绝反向（float→int 隐式）与拒绝 `bool` 参与算术（D-19 同向）都是「强类型」的题中之义。`bool` 不参与算术的额外理由：允许 `true + 1 == 2` 会让 `if x` 与 `if x <> 0` 的防线（D-19）形同虚设。
- **业界对照**：C++（同，但 C++ 的 `bool→int` 存在——Nova 收紧）、Go（**拒绝一切隐式提升**，`int32 + int64` 都报错——Nova 不学，因为 §2.6 白纸黑字写了「混合运算」）。

#### D-30 显式转换合法集

- **前状态**：§1.6 只有 `type()` 元记法。
- **新定义**：`char↔int`、`int↔float`、`int→bool(非零判定)`；`int(f)` 截断向零、越界/NaN/∞ → trap；`char(i)` 回绕不 trap；`string↔数值` 无内置（归 `uni`）。
- **理由**：`int(f)` 越界 trap 与 D-12 一致——把值装不进去是程序错误，静默回绕（C++ 的 UB）不可教；`char(i)` 回绕不 trap 的理由：`char` 本质是 7 位 ASCII 码值（D-08），`char` 运算多用于字符算术（`'a'+1`），回绕是封闭运算的自然结果，trap 会让 `for c in 'a'..'z'` 式循环（若将来支持）处处带检查。
- **业界对照**：Rust `as`（`f32 as i32` 越界在 Rust 1.45 后饱和——Nova 选 trap，理由同上）、C++（UB——拒绝）。

#### D-32 `string` 完整模型

- **前状态**：§9.2 第 2、3、4、5 条 `?`（byte/alignment、归属、internal_storage、length 属性 vs 方法）。
- **新定义**：类类型（非值类型）；变量持有 16 字节句柄 `{ptr, length}`；底层堆字节数组；`length` 属性 ≡ `length()` 方法（同一访问两种拼写）；不可变；`==` 比内容。
- **理由**：句柄模型统一回答四个未定项——byte/alignment 即句柄的 16/8（与 `&T` 一致，D-34）；`internal_storage` 即句柄中的 ptr（private，用户不可读写，但规范承认可见性以文档形式存在）；`length` 属性与方法的关系直接采用「两种拼写一个实体」（课堂倾向简洁，且 YAML 里二者并列出现本就暗示同一性）。`==` 比内容是**唯一例外**于「类类型不参与内置运算」：相等是等价关系不是算术，Go/Rust/Java(`equals`) 全数支持字符串内容比较，禁止它只会把 `s1 == s2` 推向 `uni::string_eq(s1, s2)` 的丑陋。
- **业界对照**：Go `string`（16 字节句柄 `{ptr, len}`，不可变，`==` 比内容——**几乎逐条对应**，选 Go 模型因为 Nova 的 string 接口（`length` + `internal_storage`）与 Go 的 `stringHeader` 结构同构）。

#### D-33 `array` 完整模型

- **前状态**：§9.2 第 6、10 条 `?`；§9.3 第 5 条（长度可否省略）`?`；`sort.nova:21` 的 `&array` 用法悬空。
- **新定义**：句柄 `{ptr, length}` + 行优先连续堆存储；类型中的 `n` 与运行时 `length` 冗余共存（静态可判，运行时字段服务省长度形参）；形参 `&array` = 数组顶类型（接受任意基类/长度）；`[index]` 返回元素引用。
- **理由**：`sort.nova` 的 `print_arr(a: const &array)` 已经**事实上要求**省长度形式存在，不定义它示例就无法编译；顶类型是「一个规则救三个未定项」（省长度、异构传参、`length` 运行时读取）的最小方案。
- **业界对照**：Go slice（ptr/len/cap 三元组——Nova 无动态数组故无 cap）、Rust `&mut [T]`（fat pointer ptr+len，与 Nova 句柄同构）。

#### D-34 `&T` 大小

- **新定义**：8 字节（64 位平台机器字长）。
- **理由**：引用即别名，实现为地址；ABI 已定「跨架构二进制兼容」（§2.2），64 位是唯一合理目标。规范以「实现定义但当前平台为 8」措辞留余地。

#### D-47 对齐通例

- **前状态**：§9.2 第 15 条 `?`（`alignment = byte` 是否升格为通例）。
- **新定义**：通例成立（值类型 align=size；void 0/1；类取最大成员对齐）。
- **理由**：课堂给的四组数据（1/1、1/1、4/4、8/8）呈现明显规律，笔记 §3.3 也观察到「除 void 与 class 外恰好相等」；「默认对齐」（§2.2）在业界就是 align=size 的自然对齐（System V ABI 通例）。不采「每类型单独拍」的复杂度。
- **业界对照**：System V AMD64 ABI、Itanium C++ ABI（自然对齐）。

#### D-48 成员顺序固定

- **前状态**：§9.2 第 9 条 `?`。
- **新定义**：按声明顺序，禁止重排。
- **理由**：C++ 允许重排是为了 padding 优化，代价是布局不可预测；Nova 已定「二进制兼容、携带符号表」（§2.2），**可预测布局是 ABI 兼容的前提**——链接器/不同版本编译器对同一类的理解必须逐字节一致。教学语言放弃这点优化毫无损失。
- **业界对照**：Rust `#[repr(C)]`（声明顺序）、Java（不承诺顺序——Nova 不学）。

#### D-49 vptr 置头部

- **前状态**：§9.2 第 9 条 `?`。
- **新定义**：对象头部 8 字节 vptr，计入大小；继承链基类子对象最前。
- **理由**：单继承 + 头部 vptr 是最简动态分派方案（一次取头、一次表索引）；「基类子对象最前」保证派生类指针可直接强转为基类指针（C++ 单继承同款优化）。完整对象模型归第 6 章，本章只立 ABI 前提。

#### D-50 类类型赋值=句柄复制

- **前状态**：§2.3「复杂类型传引用（参照 Python 模型）」——传参定了，**赋值**未提。
- **新定义**：赋值与传参同语义：复制句柄，`b = a` 后二者别名同一对象。
- **理由**：赋值与传参若语义分裂（C++ 深拷贝传值 vs 浅拷贝传引用）会造成学习负担；Python 模型的本义就是「名字绑定对象，赋值只复制绑定」。深拷贝需求留给第 6 章的显式拷贝操作（§2.5 暂缓项）。
- **业界对照**：Python、Java（引用类型）、Go（slice/map 句柄复制）。

#### D-51 `string.format` 内置成员方法

- **前状态**：`point.nova:15` 的 `s.format("({}, {})", x, y)` 是示例依赖，原规范与本章初稿均未定义（初稿推给第 7 章）。
- **新定义**：`s.format(fmt, args...) -> void` 是 `string` 的内置成员方法；按 `{}` 占位格式化 `args` 并写入接收者 `s` 的缓冲；前置条件 `s` 为空串（一次性初始化写入），否则移植期错误。
- **理由**：初始化语义而非运算语义，与 D-13 零值模型闭环；`point.nova` 的 `let s: string; s.format(...); return s;` 由此全程有据。
- **业界对照**：Python `str.format` 的占位规则 + Go `bytes.Buffer` 的「写入自身」形态。

#### D-52 限定名纳入 `primary-expression`

- **前状态**：§1.6 列了 `::` 运算符、`eqroot.nova:11` 在用 `math::sqrt`，但本章初稿的 `primary-expression` 只收 `identifier`，`math::sqrt(...)` 无法按文法 parse（`::` 仅在 2.7.11 一句"见第 7 章"带过）。
- **新定义**：`qualified_name = identifier { "::" identifier }` 作为 `primary-expression` 的一种；本章只固定语法形状，`::` 左操作数种类与解析规则归第 7 章（第四章 §7.4 已定义）。
- **理由**：词法与文法章必须让全部示例可 parse，语义留给后续章是正常分层；形状与第四章附录 G-2 的 `qualified_name` 逐字一致，避免两章文法打架。

### 第四组：表达式与语句（D-17 … D-25、D-35 … D-46）

#### D-17 / D-40 语句/表达式分类与块值规则

- **前状态**：§4.1「几乎一切都是表达式」+「块的值=最后一条表达式的值」，但「几乎」无边界、空块无定义、末尾是 `let`/`return` 无定义。
- **新定义**：语句清单封闭（声明/别名/导入/函数类声明/跳转）；其余皆表达式；块以非表达式语句结尾或为空 → 类型 `void`、值 `none`。
- **理由**：「几乎」必须可判定，否则文法无法写。封闭清单（5 类语句）+ 默认表达式（其余构造皆表达式）是 Rust 模式（Rust 的语句恰好也是 `let`/表达式语句/`return`/`break`/`continue` + item 声明），与 Nova 的「一切皆表达式」取向同构。块值为 `void` 而非错误，让 `{ ...; }` 作函数体（以分号语句结尾）自然成立——`hanoi.nova` 的 `void` 函数体全是这种形状。
- **业界对照**：Rust（块是表达式，单元类型 `()`）、Kotlin（`Unit`）。

#### D-18 无 `else` 的 `if` 不可作表达式

- **前状态**：§4.1 说「if 的值=所选中分支块的值」——未考虑「没选中分支」（条件假且无 else）。
- **新定义**：作表达式时 `else` 强制。
- **理由**：备选方案「缺 else 得 none」让 `let x = if c { 1 };` 在 `c` 为假时静默得 void——而 void 不可绑定（D-26），要么矛盾要么破坏 D-26；「强制 else」把决定权还给写代码的人，Rust 同款，且 Rust 社区十余年经验证明这条规则**防住的错误远多于造成的不便**。
- **业界对照**：Rust（if 作表达式必须两分支同类型且 else 必备）、Swift（同）。

#### D-19 条件必须 `bool`

- **前状态**：无明文（示例 `gcd.nova:2` 的 `if a < b` 恰好是 bool，未暴露问题）。
- **新定义**：`if`/`while` 条件类型必须 `bool`；`if x`（`x: int`）非法。
- **理由**：C 的「非零即真」是 `if (x = f())` 这类事故的根源；与 D-29（bool 不参与算术）互为表里，共同构成「布尔与数值彻底分离」的类型纪律。Java/C# 用同样纪律换来了零赋值误用类 bug。
- **业界对照**：Java、C#、Rust（三者的 `if` 都只收 `bool`）、Go（例外——允许整数真值，被广泛批评）。

#### D-20 无函数重载

- **前状态**：§1.6 只排除**运算符**重载；函数重载从未提及，但 `nvld` 的符号表设计（AGENTS.md 明示的关切）依赖这个决定。
- **新定义**：包作用域内函数名唯一，无重载。
- **理由**：重载需要名字修饰规则（AGENTS.md 四段式示例里点名的坑）+ 重载决议算法（候选集、最佳可行函数、歧义判定——C++ 教科书一整章）；Nova 的类型转换已显式化（D-30），「靠隐式转换凑参数」的重载动机不存在；`abs` 这类需求用 `math::abs_int` / `math::abs_float` 命名即可。教学语言砍掉重载是主流选择（Go、Rust、Python 均无）。
- **业界对照**：Go（无）、Rust（无，用 trait）、Python（无真重载）。

#### D-21 `match` 精确语义

- **前状态**：§5.2 给了形状和一句「obj 可以是单值、比较表达式、逻辑表达式」，匹配算法未定；`eqroot.nova:12` 的 `match d { d > 0 => ... }` 模式里**重复引用了 d**，这不是任何主流语言的 match 语义，必须给出自洽解释。
- **新定义**（2026-09-24 修订，修复原稿缺陷）：**命中判定由模式形态决定，而非 obj 形态**——比较模式（含 `< > <= >= == <>` 的表达式）求值为 `bool`、为真即命中，模式内可自由引用 `obj` 中的变量；值模式（字面量或无比较运算的表达式）求值后与 `obj` 做 `==` 比较。两类模式不可在同一 `match` 体内混用。自上而下首命中。
- **修订理由**：原稿按「obj 形态」分派（单值 obj → 模式 `==` 比较），导致 `match d { d > 0 => ... }`（obj 为单值 `d`）被解析为 `d == (d>0)`，类型错误——**规范自己的示例 2.13.2 与 `eqroot.nova` 都过不了自己的规则**。改为按「模式形态」分派后，比较模式独立求值判真，`eqroot` 与 2.13.2 均合法，且与第三章 3.3.3「按顺序执行第一个为真的分支」语义趋同。
- **业界对照**：比较模式 ≈ Ruby `case when` 条件分支 / Scala guard 的弱化版；值模式 ≈ 经典 `switch`；顺序语义同 OCaml/Rust match（首命中）。

#### D-22 `range` 身份

- **前状态**：§5.3 定了 `range(n, m, j)` 用法，未定它是什么（函数？关键字？）。若按普通函数，它返回什么类型？迭代器类型不存在（无泛型、无 trait）。
- **新定义**：`range` 是**语言内建构造**：`for` 文法特判 `range(...)` 调用形式，编译为计数循环；不存在 `range` 值，不可 `let r = range(5)`。
- **理由**：这是让 `range` 在无泛型/无迭代器类型语言中存在的**唯一**自洽方案；三参数可选（`range(n)`、`range(n,m)`、`range(n,m,s)`）与 Python 习惯对齐。代价：`for x in range(10).rev()` 之类不可做——本来也没有。
- **业界对照**：Bash `for i in {1..10}`（同为语法特判）、Rust `0..10`（Range 类型——Nova 无泛型走不了）。

#### D-23 `for-in` 可迭代对象

- **前状态**：§5.3 只给 `for x in range(...)`；笔记 §4.3 出现过 `for x in [1:10]`（切片形态）。
- **新定义**：可迭代对象 = `range` 调用、数组（表达式）、字符串（表达式）、切片；循环变量为元素只读别名。
- **理由**：`array`/`string` 已有 `[index]` 与 `length`，迭代是零新语义的糖（脱糖为 `for i in range(0, a.length())`）；切片入 `for-in` 兑现笔记里 `[1:10]` 的既有用法。只读别名（而非可写引用）的理由：可写会引入「迭代期间数组被别处改长」的悬垂问题，只读覆盖 99% 遍历场景。
- **业界对照**：Python（值副本）、Go（值副本）、Rust（`&T` 只读引用——Nova 取 Rust 的读语义但不暴露引用类型）。

#### D-24 `array` 切片

- **前状态**：§9.2 第 7 条 `?`（只给了 string 的）。
- **新定义**：支持，`[n:m]` 左闭右开，返回视图（`&array` 语义）。
- **理由**：`nova-types.yaml` 里 string 与 array 的 attributes 完全同构，课堂只给 string 切片大概率是「先写一个」而非「另一个不要」；视图语义与 string 一致（共享底层存储，不复制），越界 trap。
- **登记为待确认**：若教师本意为 array 不要切片，删除 2.6.4.2 一条即可，无连带影响。

#### D-25 / D-46 `main` 签名与退出码

- **前状态**：§9.1 第 5 条 `?`；7 个示例**全部**写 `function main() -> int { ... return 0; }`。
- **新定义**：`main() -> int` 或 `main(args: &array) -> int`（args 为 `array[string | n]`）；返回值 `mod 256` 为进程退出码。
- **理由**：示例证据压倒性（7/7 用 `-> int` + `return 0`），定义只是把事实规范化；`mod 256` 是 POSIX 退出码的现实约束，写明免得实现者各自截断。
- **业界对照**：C/C++（`int main()` / `int main(int, char**)`，退出码取低 8 位）、Go（`os.Exit` 显式——Nova 跟 C）。

#### D-35 求值顺序

- **前状态**：无。`f(g(), h())` 谁先？`a[i] = b[j]` 的 `i` 与 `j` 谁先？从未定义（C++ 曾长期未指定，C++17 才定序）。
- **新定义**：**全语言统一从左到右**；`and`/`or` 短路、`xor` 不短路。
- **理由**：未指定求值顺序是 C/C++ 初学者 bug 的头号产地（`a[i] = i++` 类）；Nova 既然现在还有机会定，就定成唯一确定的那一种——实现者没有裁量权，使用者没有惊讶。短路是 `and`/`or` 的标准语义（不短路则 `if x <> none and x.length() > 0` 无法写）。
- **业界对照**：Java（操作数严格左到右——Nova 同款）、Python（左到右）、C++17（部分定序——Nova 更进一步全定序）、Go（未指定——Nova 拒绝）。

#### D-36 作用域模型

- **前状态**：无。块作用域/全局变量/shadowing/前向引用全部未提。
- **新定义**：四级作用域（包/文件/函数/块）；块作用域；允许 shadowing、无逃逸语法；块变量无前向引用，包级函数/类允许前向引用。
- **理由**：块作用域是「一切皆表达式 + 块有值」模型的必然配套（`if { let tmp = ...; }` 的 tmp 不该漏出去）；允许 shadowing 而禁止逃逸（无 C++ 式 `::name` 访问全局）保持名字解析单一规则；函数/类前向引用是无头文件模型的必然要求（`inherit.nova` 的 `tiger` 在 `felid` 之后定义只是巧合，两趟解析才能任意排序）。
- **业界对照**：Rust（块作用域 + shadowing 自由）、Go（块作用域 + shadowing）、Java（局部变量禁止 shadow 局部——Nova 不学，教学收益低）。

#### D-37 生命周期

- **前状态**：无。`let &a = c;` 的悬垂问题从未讨论，但引用是别名（§2.4）就意味着悬垂引用是**内存安全**问题。
- **新定义**：三类存储期；静态可判定的悬垂 → 移植期错误；不可判定 → trap；规范承诺「不存在可观察的悬垂引用」。
- **理由**：无 GC 承诺、无所有权系统（教学语言不现实），唯一诚实的方案是把「何时报错」写进规范而把「怎么检测」留给实现（借用检查/引用计数/保守 trap 均可）。
- **业界对照**：Rust（编译期全判——Nova 无力也无必要做到）、Java（引用对象永不自愈悬垂——GC 兜底，Nova 的回收策略归第 6 章/实现阶段）。

#### D-38 值类别

- **前状态**：§2.4 引用是别名，但「什么表达式可放 `=` 左边」从未定义。
- **新定义**：左值/右值二分；左值集封闭（变量、字段、索引结果、引用别名）；`a+b=c` 语法错误。
- **理由**：`[index] -> reference`（YAML）已经**要求**索引表达式产生左值，不定义值类别就无法陈述这条；赋值左值检查是移植期错误清单（2.10.1）的前提。
- **业界对照**：C++（glvalue/prvalue 三分——Nova 取经典二分，无移动语义故无需更细）。

#### D-39 类类型 `==` 同一性

- **前状态**：§2.6「类类型不参与内置运算」，但 `==` 是否算「运算」未明；自定义类型如何比较是 §9.3 第 6 条 `?`。
- **新定义**：`==`/`<>` 对类类型可用，语义为**引用同一性**；内容比较归第 6 章（`__equals__` 钩子或 `uni` 函数，本章不拍板）；`string` 例外比内容（D-32）。
- **理由**：同一性比较零成本（比指针）且是 `if t = t2` 类恒等测试的刚需；内容比较涉及虚分派（第 6 章）故本章不越权。
- **业界对照**：Java `==`（同一性）/`equals`（内容）二分——Nova 同款；Go `==`（结构相等——Nova 不学，因为有继承与 vptr 的对象结构相等语义不清）。

#### D-41 `$` 无语义

- **前状态**：§9.3 第 4 条 `?`；`point.nova:8` 用 `$x` 区分形参与字段。
- **新定义**：`$` 是普通标识符字符，无任何语言规则；`$x` 是书写约定。
- **理由**：§1.2 标识符文法已含 `$`，若再赋予语义（如「`$` 前缀=形参」）会产生「无 `$` 前缀的形参非法」的荒谬推论（`gcd(a: int, b: int)` 全中枪）。约定与规则分离，一句话关闭此未定项。

#### D-42 `async`/`await`/`yield` 保留

- **前状态**：§9.3 第 3 条 `?`；关键字表里有，语义无。
- **新定义**：三词保留，出现即语法错误，并发模型留待后续。
- **理由**：词法章必须回答「这三个关键字现在能干什么」——答案是「不能干什么」，但必须明说，否则实现者会去猜协程还是线程。保留而非删除：删了将来加回是破坏性变更，保留则将来只增语法。

#### D-43 字符串拼接与 `format` 方法

- **前状态**：无。`+` 排除于类类型（§2.6），拼接无处安放；`point.nova:15` 用 `s.format(...)`——又一个未登记的「示例依赖」。
- **新定义**（2026-09-24 修订，修复原稿缺陷）：拼接经 `uni::concat`（第 7 章）；**`s.format(fmt, args...) -> void` 定为 `string` 内置成员方法**（登记 D-51），一次性写入空串接收者。原稿把 `format` 推给第 7 章「再定」，导致 `point.nova` 在第二章体系下无据可依——示例依赖必须在本章闭环。
- **理由**：守「类类型不参与内置运算」的纪律（D-32 的 `==` 例外已论证过边界，拼接是**生成新对象**的运算，性质不同，不豁免）；`format` 不生成新对象而是写入自身，性质是**初始化**而非运算，与零值模型（D-13）配套。

#### D-44 无元组类型

- **前状态**：多重赋值（D-15）是否引入元组值未定。
- **新定义**：无元组类型；多重赋值是文法构造。
- **理由**：元组一旦存在，`f((1, 2))`、`(a, b) = g()`、异构 `array[(int, string)]` 会连锁要求泛型/结构相等/解构——每个都是无底洞；砍掉元组，交换惯用法（唯一动机）由 D-15 直接满足。

#### D-45 函数类型有限一等

- **前状态**：无。`function` 能否作值从未讨论。
- **新定义**：函数可作为实参传递（函数值），**不可**存入字段/数组；不可比较。
- **理由**：高阶函数是「排序按不同键」这类教学刚需（`select_sort` 的将来形态）；存储需要函数指针的 ABI 布局（fat pointer 问题），推迟到第 6/7 章。最小开放。

## 6. 风险提示（需教师裁决的三处）

以下三条的新定义**存在与教师本意相反的可能**，若课堂结论不同，按课堂改：
