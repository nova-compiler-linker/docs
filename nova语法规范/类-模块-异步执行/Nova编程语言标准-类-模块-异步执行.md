### 6.1 类声明 `✔` [class.decl]

**[1]** 类声明引入一个新的**类类型**（class type）。类类型属于 §2.1 的「类类型」大类。

**[2]** 类名是标识符（§1.2）。同一模块内，类名**不得**与其它顶层声明（类、函数、`type` 别名、常量、导入名）重名；
违反者为**格式错误**。

**[3]** 类**只能**声明在模块顶层（§7.1）。**不允许**嵌套类（类内声明类）与局部类（函数体内声明类）——
这样模块的符号表是扁平的，`nvc` 与 `nvld` 的名字解析、修饰规则（§7.7）都只需一层。

**[4]** 模块内的名字解析采用**两遍扫描**：同一模块内所有顶层声明互相可见，**与书写顺序无关**，
因此**不需要**前向声明（对比 C++ 必须有头文件或前向声明）。跨模块引用见 §7.3。

**[5]** 类声明的值是 `none`（§4.1：一切皆表达式）。

**[6]** 类声明以 `}` 结束，其后**可以**跟一个冗余的 `;`（两种写法语义相同）。

**[7]** 空类（不含任何字段）合法，其布局见 §6.11 [5]。

**例：**

```nova
class point {
    private {
        x: float;
        y: float;
    }

    public {
        function __constructor__($x: float, $y: float) {
            x = $x;
            y = $y;
        }

        function __to_string__() -> string {
            let s: string;
            s.format("({}, {})", x, y);
            return s;
        }
    }
}
```

### 6.2 成员与访问组 `✔` [class.member]

**[1]** 类的成员分三类：**字段**（§6.3）、**成员函数**（§6.4）、**静态成员**（§6.8）。

**[2]** 每个成员**必须**写在 `public` / `protected` / `private` 三个**访问组**之一的 `{ }` 内；
**不提供**默认访问级别，类内裸写成员声明为**格式错误**。

**[3]** 同一个访问级别**可以**出现多次，按出现顺序合并处理；访问组的书写顺序不影响对象布局（§6.11 [1]）。

**[4]** 访问级别的含义：

| 访问级别 | 可访问的位置 |
|---|---|
| `public` | 任何可见该类的代码 |
| `protected` | 本类的成员函数、以及本类派生类的成员函数 |
| `private` | 仅本类的成员函数（含构造函数） |

**[5]** `private` 成员在派生类中**不可访问**，也不参与重写（§6.7 [4]）。

**[6]** 派生类成员函数访问**基类** `protected` 成员时，被访问对象的静态类型**必须**是本类或本类的派生类
（以 `self` 访问恒满足此条件）。违反者为**格式错误**。

> 注：这条规则（源自 C++）禁止用「基类类型的引用」去访问另一个对象的 `protected` 成员，否则派生类可以借
> 基类接口互相窥探私有实现。

**[7]** 访问控制在**编译期**检查。违反访问级别者为**格式错误**，实现**必须**诊断。
运行时**没有**任何访问检查：本语言没有反射，也没有 RTTI（§6.12）。

**[8]** 本语言**没有** `friend`、**没有**「同包可见」这类旁路。

**[9]** 访问级别**不影响**对象布局、方法表槽位与名字修饰：改变成员的访问级别不改变 ABI 的数据布局，
但会改变跨模块可见性与可重写性。

### 6.3 字段 `✔` [class.field]

**[1]** 字段的语法为 `name : type ;` 或 `name : type = expr ;`。

**[2]** 字段名在**整条继承链**上**必须**唯一：派生类**不得**声明与任何基类同名的字段（无论访问级别）。
违反者为**格式错误**。

> 注：这与 C++ 的字段隐藏（shadowing）不同。禁止字段隐藏消除了「同名两个存储位置」带来的布局歧义，
> 使「裸名 = 一个确定的存储位置」始终成立。需要改变含义时请用不同的名字或重写成员函数。

**[3]** 字段的类型**可以**是值类型或类类型（§2.1）。

**[4]** 无初值的字段在对象创建时被**清零**（§6.5 [6] 步骤 ①）。但**类类型字段不能靠零值表示「无对象」**：
本语言**不存在空引用**（对比 C++ 的 `nullptr`），`none` 是 `void` 的值（§1.5），**不是**任何类类型的值。
因此类类型字段的初始化由**编译期检查**保证，规则如下：

```
① 字段声明处有初值            → 该字段视为已初始化
② 否则：本类的每一个构造函数都必须在**所有正常退出路径**上为它赋一个类类型的值
   （含 `string` / `array` 这类内置类类型；它们的默认值见 §2.6，尚未定稿，故不计入「已初始化」）
③ 隐式生成的无参构造函数（§6.5 [4]）体为空，因此只有当**本类所有类类型字段都有声明初值**时它才可用；
   否则该类必须显式声明构造函数
④ 检查只覆盖**本类声明的**字段：基类字段由基类自己的构造函数负责（编译基类时已检查）
```

违反 ② 或 ③ 者为**格式错误**——`nvc` **必须**做「类类型字段必然赋值」检查
（效果等同 C# 的 definite assignment、Rust 的未初始化检查）。

> 注：清零只对值类型字段给出确定的 `false` / `'\0'` / `0` / `0.0`。类类型字段在构造完成前**没有可观察的值**：
> 上面的检查保证任何**构造成功返回**的对象，其类类型字段都已指向一个真实对象。
> 构造期间把 `self` 传出、并由他人在赋值之前读取该字段，属 §6.5 [11] 的**未定义行为**。

**[5]** 声明为 `const` 的字段**必须**在声明处给出初值，且在构造函数体结束后**不得**再被赋值。

**[6]** 字段可以在任何能访问它的地方作为**左值**使用：`p.x = 3.0;`。赋值表达式的值是 `none`（§4.1）。

**[7]** 字段**不**参与动态分派，也不占方法表槽位；字段访问是静态的（偏移在编译期确定，见 §6.11）。

**[8]** `string` / `array` 的「字段」由内置接口给定（§2.6、`nova-types.yaml`），本部分不为其增设成员。

### 6.4 成员函数、`self` 与名字查找 `✔` [class.mem]

**[1]** 成员函数以 `function name(参数列表) [-> 返回类型] { 体 }` 定义，或以 `;` 结尾**只声明**。
只声明的成员函数**必须**在**同一模块内**用 `类名::函数名` 的形式给出定义；否则为**链接期错误**
（不是格式错误：名字与类型已经检查通过，缺的是定义）。

```nova
class counter {
    public {
        function bump() -> int;          # 只声明
    }
}

function counter::bump() -> int {        # 同模块内定义
    return 0;
}
```

**[2]** 成员函数体内有一个隐式形参 **`self`**，它是对本类对象的引用（§2.4）。`self` 的类型不可书写
（没有类类型引用的书写形式），也不能被赋值。

**[3]** 成员函数体内访问本类（含基类）成员的裸名解析顺序为：

```
1. 局部变量与形参（最近的作用域优先）
2. 本类及其基类的成员（派生类的成员遮蔽同名的基类成员）
3. 本模块的顶层名字（§7.4）
4. 通过 import 引入的名字（§7.3）
5. uni 包的预导入名字（§7.6）
```

第 2 步命中时等价于 `self.成员`；派生类成员遮蔽基类成员时，基类成员用 `super.成员` 显式访问（§6.6 [7]）。

**[4]** 局部变量或形参与字段同名时，**局部名遮蔽字段名**，字段必须用 `self.名字` 访问。

**[5]** 形参名**可以**以 `$` 开头（`$x`）。`$x` 与 `x` 是**两个不同的标识符**（§1.2 允许 `$` 作首字符），
因此 `$x` 形式的形参**不会**遮蔽同名字段，也不需要 `self.` 前缀。

> 注：`point.nova` 里 `function __constructor__($x: float, $y: float) { x = $x; y = $y; }` 用的就是这个办法。
> **本规范确认：`$` 前缀是约定，不是特殊语法**——它完全由 §1.2 的标识符规则推出，语言不为其增设任何规则。
> 这条结论销掉了 `nova-spec.md` §9.3 第 4 项。

**[6]** 成员函数内可以直接调用本类的其它成员函数（裸名）。`self.名字(...)` 与裸名等价。

**[7]** 在成员函数体内，`self` 可以作为实参传给别的函数，也可以作为返回值（返回的是对象的引用）。

**[8]** 成员函数**可以**重载：同一类内、或派生类相对基类，**可以**有多个同名成员函数，只要**参数类型列表不同**。
返回类型**不**参与区分。两个仅返回类型不同的同名同参函数为**格式错误**。

**[9]** **重载解析**只看实参的**静态类型精确匹配**，不引入重载专用的隐式转换
（`int` ↔ `float` 的混合提升是否存在见 `nova-spec.md` §9.2 第 11 项；即使存在，也不参与候选匹配）。
若多个候选同等匹配，为**格式错误**——歧义**必须**显式消解（与 §7.4 [6] 同一取向）。

> 注：本规则以「本语言不存在隐式类型转换」为前提。若课程后续决定引入转换（§9.2 第 11 项），
> 重载解析**必须**重新定义（例如改成「不差于」排序），否则 `f(1)` 这类调用会同时匹配 `f(int)` 与 `f(float)`。

**[10]** 成员函数**允许**被重写而不需任何额外关键字；是否需要 `override` 的判定规则见 §6.7 [2]。

**[11]** 成员函数不占对象存储；每个成员函数在方法表中占一个槽位（`private` 与 `static` 函数除外），见 §6.11 [7]。

**[12]** 模块级函数（非成员函数）的规则与成员函数的差别只有两点：没有 `self`，不在方法表中占槽位。

### 6.5 构造与对象创建 `✔` [class.ctor]

**[1]** 构造函数是以 **`__constructor__`** 为名的成员函数。构造函数**不写**返回类型，也不能写 `-> 类型`
（写者为**格式错误**）。构造函数体内可以用不带值的 `return;` 提前结束。

**[2]** 构造函数是**普通成员函数**：它可以重载（§6.4 [8]），可以被访问组限定（通常为 `public`），
可以调用其它成员函数。

**[3]** 对象由「类名作为被调用者」的调用表达式创建：`point(1.2, 3.4)`、`tiger()`。
类名后跟实参列表即构造调用；**没有 `new`，也没有 `delete`**（`✗`，见 §6.12）。

**[4]** 若类**没有**声明任何构造函数，则隐式生成一个**无参构造函数**，其函数体为空：
有初值的字段取初值；无初值的**值类型**字段取零值；**类类型字段必须都有声明初值**，
否则该隐式构造函数**不可用**（§6.3 [4] ③）。

**[5]** 若类**只**声明了带参数的构造函数，则**不存在**隐式无参构造函数；此时 `T()` 是**格式错误**。

**[6]** 构造一个类型为 `D` 的对象，按下列顺序执行（`B` 为 `D` 的直接基类，若有）：

```
① 分配对象存储并将全部字段清零（值类型字段取零值；vptr 置为 D 的方法表，构造期间的分派规则见 §6.7 [6]）
② 执行基类构造函数 B.__constructor__(...)      （若有基类；必须显式书写，见 [7]）
③ 按声明顺序求值 D 自己的字段初值 expr          （只对有初值的字段）
④ 执行 D 的构造函数体
⑤ 构造完成，对象引用交给调用者
```

**[7]** 基类构造函数**不会自动调用**：派生类构造函数**必须**显式写出基类构造调用
`super.__constructor__(实参);`。唯一的例外是 [8]。

**[8]** 若基类存在**无参**构造函数（含 [4] 的隐式无参构造函数），则派生类构造函数**可以**省略
`super.__constructor__();`；省略等价于在 [6] 的**第 ② 步**调用基类的无参构造函数。
若基类**没有**无参构造函数，省略基类构造调用为**格式错误**。

**[9]** **书写位置**与**执行时机**是两件事，必须分开理解：

| | 规则 | 违反后果 |
|---|---|---|
| **书写位置** | 显式写出的 `super.__constructor__(...)` **必须**是构造函数体的**第一条语句** | **格式错误** |
| **执行时机** | 它在 [6] 的**第 ② 步**执行——即在本类字段初值（第 ③ 步）**之前**，而不是跟着构造体（第 ④ 步）走 | 实现必须按 [6] 的顺序生成代码 |

> 注：书写位置固定为体首，是为了让「基类先构造」在源码上一眼可见、不可能被夹在别的语句之间；
> 执行时机固定在字段初值之前，是为了让字段初值可以安全地使用基类已构造好的状态（§6.3 [4] 的
> 「类类型字段必然赋值」检查也依赖这个顺序）。两者并不冲突——**源码上的第一句 ≠ 执行顺序上的最后一步**。

> 注：把基类构造固定在第 ② 步、把字段初值固定在第 ③ 步，使「对象在任何时刻都处于确定的构造阶段」，
> 这是 `nvc` 生成代码与调试器观察对象的依据。这与 C++ 的「基类 → 成员 → 函数体」次序一致。

**[10]** 类类型是**引用语义**（§2.3，参照 Python 模型）：变量、字段、实参保存的是**对对象的引用**，
不是对象的副本。因此

```nova
function demo() -> void {
    let a = point(1.0, 2.0);
    let b = a;          # b 与 a 引用同一个对象，不产生副本
    b.translate(1.0, 0.0);
    # 此时 a 观察到的对象也被改动了
}
```

**[11]** 构造期间把 `self` 传出（作为实参、返回值或存入其它存储），接收方**不得**在构造完成前访问该对象；
违反者的行为**未定义**。构造完成前调用被更派生类重写的函数，按**正在构造的类**分派（§6.7 [6]）。

**[12]** 构造没有返回值，也**没有失败通道**：本语言没有异常（`✗`），构造函数不能报告失败。
需要「可能失败的创建」时，用**输出参数 + 状态返回值**的静态工厂函数表达：

```nova
# 约定：返回 false 表示失败；成功时把结果写入 result 指向的对象
# 调用方必须传入一个已构造的 point（本例用 point(0.0, 0.0) 占位）
function point_parse(s: &string, result: &point) -> bool { ... }

function demo(s: &string) -> void {
    let p = point(0.0, 0.0);
    if point_parse(s, p) {
        println("{}", p);
    } else {
        println("parse failed");
    }
}
```

**不得**用 `none` 表示「创建失败」：`none` 是 `void` 的值（§1.5），而类类型**没有空值**（§6.3 [4]）；
让一个声明为 `-> point` 的函数返回 `none` 会破坏强类型。完整的错误编码约定属《标准库》部分
（附录 B-2 第 4 项）。

**[13]** 对象存储由运行时自动回收：**没有 `delete`，也没有析构函数**（`✗`，见 §6.12 [7]）。
回收算法属**实现定义**（引用计数或追踪式回收均可），但**必须**满足：

- **不可达的对象必须最终被回收，包括不可达的引用环**：类类型字段可以构成环（`a.next = b; b.next = a;`），
  纯引用计数**无法**回收这种环，因此实现**必须**采用追踪式回收，或采用**带循环收集**的引用计数
  （纯引用计数不满足本条）；程序不会因遗忘释放或循环引用而泄漏；
- 回收**不得移动**对象：对象地址在整个生存期内稳定（这是 §2.4 的 `&` 引用与 §7.7 原生包互操作的前提）；
- 回收所需的元数据**不属于** §6.11 规定的对象布局（实现可以把它放在对象之外）。

**[14]** 本语言**不提供隐式对象拷贝**。需要副本时，显式声明一个构造函数并用构造调用产生它：

```nova
class vec2 {
    public {
        x: float;
        y: float;

        function __constructor__($x: float, $y: float) { x = $x; y = $y; }
        function __constructor__(other: &vec2) { x = other.x; y = other.y; }   # 显式拷贝
    }
}

function demo() -> void {
    let a = vec2(1.0, 2.0);
    let b = vec2(a);        # 复制品，与 a 无关
}
```

> 注：这条结论销掉了「类对象的拷贝语义」在本部分的缺口：**引用绑定是默认语义，复制必须显式**。
> 它与 `nova-spec.md` §2.5 的暂缓项相容——本部分不引入隐式拷贝规则，因此不需要先定 §2.5。

**[15]** 类类型上的 `==` / `<>` 比较的是**对象身份**（是否为同一个对象），不是内容相等。
由于本语言不要运算符重载（§1.6），内容相等**必须**用普通成员函数表达，命名由库约定（例如 `equals`）。

### 6.6 继承 `✔` [class.derived]

**[1]** 继承在类名之后用 `<-` 写出：

```nova
class tiger <- public felid {
    public { ... }
}
```

**[2]** 继承访问说明符**必须**显式写出（`public` / `protected` / `private` 之一），省略为**格式错误**。

**[3]** **本版本只允许单继承**：`<-` 后只能有一个基类。多继承为**明确排除项**（`✗`，见 §6.12 [1]）。

**[4]** 继承访问说明符决定基类成员在派生类中的访问级别：

| 写法 | 基类 `public` 成员 | 基类 `protected` 成员 | 基类 `private` 成员 |
|---|---|---|---|
| `<- public B` | 仍为 `public` | 仍为 `protected` | 不可访问 |
| `<- protected B` | 降为 `protected` | 降为 `protected` | 不可访问 |
| `<- private B` | 降为 `private` | 降为 `private` | 不可访问 |

**[5]** 基类**必须**在派生类所在模块中**可见**（同模块声明，或经 §7.3 的 import 引入），
且**必须**是完整声明的类（不是 `type` 别名指向的不完整类型）。违反者为**格式错误**。

**[6]** 继承关系**不得**成环；循环继承为**格式错误**。

**[7]** `super` 引用**直接基类**：`super.成员` 访问基类成员（含被派生类遮蔽的成员），
`super.__constructor__(...)` 调用基类构造函数。`super` **只能**出现在本类的成员函数体内
（含构造函数）；在没有基类的类内使用 `super` 为**格式错误**。

**[8]** 派生类与基类同名同签名的成员函数构成**重写**，必须写 `override`（§6.7 [2]）。
派生类与基类同名但不同签名的成员函数构成**重载**：它不重写基类函数，而是**遮蔽**基类的同名重载集合——
被遮蔽的基类版本必须用 `super.名字(...)` 才能调用。

```nova
class base {
    public {
        function f(a: int) -> void { }
        function f(a: int, b: int) -> void { }     # 重载：基类有两个 f
    }
}

class derived <- public base {
    public {
        function f(a: string) -> void { }          # 重载（不同签名），遮蔽 base 的两个 f
        function g() -> void {
            super.f(1);        # 取被遮蔽的基类版本
            f("hi");           # 取本类版本
        }
    }
}
```

**[9]** 派生类**不得**声明与基类同名的**字段**（§6.3 [2]）。

**[10]** 派生类的对象**包含**基类子对象（§6.11 [1]）；基类的 `private` 成员仍在对象存储中占位，
只是不可访问。

**[11]** 本语言**没有** `final`、**没有**抽象类、**没有**接口/`trait`（`✗`，见 §6.12）。
所有类都可以被继承，所有 `public` / `protected` 成员函数都可以被重写。

本版本的**布局不排斥**将来新增接口 / 混入：接口不需要对象存储，也不需要第二个 `vptr`
（它的方法可以不占 §6.11 [7] 的槽位或按约定追加），因此「单继承 + 接口/混入」在将来是一条**加法**路径，
不会推翻 §6.11 的布局与二进制兼容规则——但它**需要新语法与一次课程确认**，
所以本版本既不实现、也不预留语法。

> 注：`nova-spec.md` §9.1 第 3 项（`<-` 的完整规则、继承处 `public` 的含义、是否多重继承）由本条 [2][3][4] 定稿。
> 与早期速记「多继承用 `,` 隔开」的冲突及取舍理由，见《设计取舍报告》第 2 节。

### 6.7 重写与动态分派 `✔` [class.virtual]

**[1]** `override` 修饰成员函数的**定义**或**声明**：`override function cry() -> void { ... }`。

**[2]** 判定规则（**必须**诊断，两条都是格式错误）：

- 若派生类的成员函数与某个**可访问的**基类成员函数**签名完全相同**（名字 + 参数类型列表），
  则**必须**写 `override`；漏写为**格式错误**（防止把「本想重写」写成「无意遮蔽」）。
- 若写了 `override` 却在基类中找不到签名相同的成员函数，为**格式错误**。

**[3]** 签名相同要求**返回类型也相同**：本语言**不允许**协变返回类型。

**[4]** 参与重写与动态分派的成员函数**必须**是 `public` 或 `protected` **且非 `static`**：

- `private` 与 `static` 成员函数**不参与**重写：它们在派生类中不可见，`override` 它们为**格式错误**；
- 对它们的调用是**静态**的（编译期确定目标）。

**[5]** 本语言**没有** `virtual` 关键字：所有 `public` / `protected` 的非静态成员函数**天生可以**被重写
（等价于 C++ 的 `virtual`）。因此**所有**这类调用（除 [6] 与 [4] 的例外）都按**对象的动态类型**分派。

```nova
class felid {
    protected { name: string; }
    public {
        function __constructor__(n: &string const) { name = n; }
        function cry() -> void { println("a {} cries", name); }
    }
}

class tiger <- public felid {
    public {
        function __constructor__() { super.__constructor__("tiger"); }
        override function cry() -> void { println("a {} roars", name); }
    }
}

function main() -> int {
    let t: felid = tiger();     # 向上转换，见 [8]
    t.cry();                    # 动态分派到 tiger::cry —— 输出 "a tiger roars"
    return 0;
}
```

**[6]** 在类 `C` 的构造函数体执行期间，对成员函数的调用按 **`C`** 分派（**不**向下分派到更派生的类）。
构造完成后按对象的动态类型分派。

> 注：这条规则保证构造函数看到的对象状态是「已经构造好的那一部分」，避免调用到尚未初始化字段的更派生实现
> （C++ 用「构造期间 vptr 逐级切换」达到同样效果）。实现可以用一个 vptr 加临时切换实现，见 §6.11 [3]。

**[7]** 动态分派的实现载体是**方法表**（§6.11 [7]）。方法表是 ABI 的一部分：同一类在两个编译单元中的
槽位分配**必须**一致，否则跨模块调用的结果未定义。

**[8]** **向上转换**（派生类引用 → 基类引用）是隐式的，无需 `type()`；**向下转换**（基类 → 派生类）
在本版本中**不提供**（`✗`，见 §6.12 [8]），因此不需要运行时的类型信息（RTTI）。

```nova
function demo(u: felid) -> void {
    let t: felid = tiger();         # 合法：向上转换
    let v: tiger = u;               # 格式错误：不存在向下转换
}
```

**[9]** 若一个类方法的签名与某个基类方法相同但 `async` 修饰不同，为**格式错误**（见 §8.5 [3]）。

### 6.8 静态成员 `✔` [class.static]

> 本节销掉 `nova-spec.md` §9.3 第 1 项（`static` 关键字存在但无用例）。

**[1]** `static` 修饰类成员，写在字段或函数声明之前：

```nova
class counter {
    private {
        static total: int = 0;
    }
    public {
        static function bump() -> int {
            total = total + 1;
            return total;
        }
    }
}
```

**[2]** **静态字段**每个类只有**一份**存储（不属于任何对象），生存期与程序相同。
静态字段的初值**必须**是**常量表达式**（编译期可求值），因此**不存在**静态初始化顺序问题。

> 注：常量表达式初值让静态字段可以直接落在只读/数据段里，运行时不需要「模块初始化函数」，
> 于是 §7.3 的循环 import 也不会引发初始化顺序问题。

**[3]** **静态成员函数**没有 `self`：函数体内**不得**使用 `self`，**不得**用裸名访问实例字段或实例成员函数
（用 `对象.成员` 显式访问是合法的）。

**[4]** 静态成员的访问用 `::`（§7.4）：`counter::bump()`、`counter::total`。
用对象访问静态成员（`c.bump()`）为**格式错误**，避免「看起来像实例调用」的歧义。

**[5]** 静态成员同样受访问组限制（`counter::total` 是 `private`，类外访问为格式错误）。

**[6]** 静态字段**不占**对象存储；静态成员函数**不占**方法表槽位，也不参与重写（§6.7 [4]）。

### 6.9 内置钩子与保留名 `✔` [class.hook]

**[1]** 形如 `__名字__`（双下划线开头且结尾）的标识符是**保留标识符**。除本规范定义的钩子外，
用户声明或使用 `__名字__` 为**格式错误**。

**[2]** 本版本定义的钩子：

| 钩子 | 语义 | 条款 |
|---|---|---|
| `__constructor__` | 构造函数 | §6.5 |
| `__to_string__() -> string` | 类类型值的文本化，用于 `{}` 占位格式化 | [3] |

**[3]** `println` / `print` 的 `{}` 占位遇到类类型值时（`string` 的 `format` 方法同理，见 §7.6 [3] 的说明）：

- 若该类定义了 `__to_string__() -> string`，调用**动态类型**版本（动态分派），用其返回值填充；
- 若未定义，填充为该类的**类名**（例如 `point`）。这是一条确定的结果，不输出地址，也不依赖实现。

**[4]** 本版本**不定义**相等、哈希、比较钩子：`==` / `<>` 对类类型恒为身份比较（§6.5 [15]），
`<` `>` `<=` `>=` 对类类型不可用（§2.6：类类型不参与内置运算）。

**[5]** 本版本**不定义**析构钩子（`__destructor__` 之类）：对象回收由运行时负责且时机不确定（§6.5 [13]），
提供析构只会给出「确定的回收时机」这一错觉。需要释放外部资源时，用显式的成员函数（如 `close()`）
并由调用者负责调用。

### 6.10 类与模块的边界 `✔` [class.module]

**[1]** 类的**可见性**由它所在的模块决定：顶层声明默认导出；被 `private` 修饰的类是**模块私有**的（§7.5）。
模块私有的类**不得**出现在任何跨模块可见的函数签名、字段类型或基类列表中，违反者为**格式错误**。

**[2]** 一个类**只能**在**一个**模块中定义一次。同一模块内重复定义同名类为**格式错误**；
两个不同模块定义同名类时，它们是**两个不同的类**，除非用限定名区分，否则跨模块引用会因歧义而格式错误（§7.4）。

**[3]** 没有头文件（§7.1）：类的成员函数、字段、布局的全部信息都在其定义所在模块中，
通过 `nvp` / `nvld` 产出的**符号表与元数据**跨模块传播（§7.7）。

**[4]** 跨模块继承要求基类可见（§6.6 [5]）；跨模块调用成员函数要求类可见且成员可访问（§6.2 [7]）。

### 6.11 对象布局与 ABI `✔` [class.layout]

> 本节是 `nova-spec.md` §2.6 中「`class`：byte 视成员数量、alignment 取最大成员的对齐」的**细化**，
> 并销掉其 §9.2 第 9、10、11 项（方法表指针、成员排布顺序、继承时的布局）。

**[1]** 单继承下，对象 `D <- B` 的内存布局为：

```
偏移 0            : vptr（方法表指针，指向 D 的动态类型方法表）
vptr 之后         : B 的字段（含 B 的基类字段，递归展开），按声明顺序
                  : D 新增的字段，按声明顺序
                  : 尾部填充，使总大小为其对齐的整数倍
```

- 每个对象**只有一个** `vptr`，位于偏移 0，跨访问组不变；
- 字段按**声明顺序**排布，访问组的书写顺序不影响位置；
- 每个字段按自身类型的对齐要求（§2.6）放置，必要时插入填充。

**[2]** 类类型的大小与对齐：

```
align(class) = max( vptr 的对齐, 所有字段对齐的最大值 )        # 空类时即为 vptr 的对齐
size(class)  = 填充后的偏移总量，向上取整到 align(class) 的整数倍
```

`vptr` 的宽度与对齐由目标平台的调用约定（ABI）决定，属**实现定义**。

**[3]** `vptr` 的内容是**动态类型**的方法表地址。构造过程中的分派语义见 §6.7 [6]。
**对外 ABI 只有一种模型**：完整类对象在偏移 0 有**唯一**一个 `vptr` 槽位，`sizeof` 与所有字段偏移
一律按 [1][2] 计算。构造期间实现**可以临时改写该槽位的内容**（逐级切换，用以落实 §6.7 [6]），
但**不得**在对象布局中增加任何额外槽位，也**不得**改变 `sizeof` 或字段偏移。
原生包（§7.8）看到的始终是这一种布局，因此不存在「按层各带一个 `vptr`」的第二种 ABI。

**[4]** 静态字段不占对象存储；成员函数不占对象存储。

**[5]** 空类（无字段）的大小 = `vptr` 的宽度，对齐 = `vptr` 的对齐。

> 注：这修正了「空类 0 字节」的直觉。因为 `override` 需要动态分派，每个对象都必须携带 `vptr`，
> 所以类对象永远不为 0 字节。这条结论与 §2.6 的「视成员数量」相容：`vptr` 由实现隐式加入。

**[6]** 对象在堆上分配、**不可移动**（§6.5 [13]）。垃圾回收的元数据**不属于**本布局，
实现可以放在对象之外（例如旁路表），从而保持本布局的 ABI 稳定。

**[7]** **方法表**的布局规则：

```
槽位 0 .. k-1 : 沿继承链从最基类到 D 的所有「可分派成员函数」（public/protected 且非 static）
                按「基类先、声明顺序在后」排列
override f    : 复用 f 在基类中的槽位，槽内地址替换为 D 的实现
新增函数 g    : 追加一个新槽位（包括新增的重载）
static / private 成员函数 : 不占槽位
```

由此得到二进制兼容规则。「兼容」以**改动发生的位置**为前提：追加到**最派生类**的末尾才安全，
追加到**任何被继承过的类**上都会移动其派生类部分（字段偏移或槽位下标），因此**不**兼容。

| 改动 | 二进制兼容 |
|---|---|
| 在**最派生类**（无派生类的类）末尾**追加**字段 | 兼容（旧布局是新布局的前缀） |
| 在**基类**中追加字段（该类有派生类） | **不**兼容：派生类的字段偏移整体后移 |
| 在**最派生类**末尾**追加**成员函数 | 兼容（新槽位追加在末尾） |
| 在**基类**中追加成员函数（该类有派生类） | **不**兼容：派生类新增函数的槽位整体后移 |
| 在继承链**中间插入**字段、或重排字段声明顺序 | **不**兼容 |
| 改变已有成员函数的签名或名字 | **不**兼容 |
| 改变成员函数的 `override` 目标 | 兼容（只换槽内地址） |
| 改变访问级别（不改布局） | 数据布局兼容，可见性随之变化 |
| 在继承链中间插入一个类 | **不**兼容 |

> 注：`vptr` 槽位**从一开始就存在**（[1][5]），因此「给一个原本无可分派函数的类新增第一个可分派函数」
> 只改变方法表内容（本表最后一行的追加规则），**不**改变字段偏移或对象大小。

**[8]** 类类型与 `type()` 显式转换（§1.6）：

- 派生类 → 基类：**隐式**允许，也可写 `type()`，恒安全；
- 基类 → 派生类：**不提供**（§6.7 [8]）；
- 类类型 ↔ 值类型：**不提供**。

### 6.12 明确排除项 `✗` [class.excluded]

| # | 排除项 | 理由 / 替代 |
|---|---|---|
| 1 | **多继承**（`<- A, B`） | 需要多 `vptr`、名字歧义、菱形基类等一整套规则，与 §6.11 的可预测布局冲突；替代：单继承 + 组合（把另一个对象作为字段）。早期速记里的「`,` 隔开多继承」按**排除**处理，论证见《设计取舍报告》第 2 节 |
| 2 | 嵌套类 / 局部类 | 保持模块符号表扁平（§6.1 [3]）；替代：模块内平级声明另一个类 |
| 3 | `friend` / 同包可见旁路 | 访问控制只有三档（§6.2 [4]） |
| 4 | 抽象成员 / 接口 / `trait` / `final` | 本版本不做；「必须被重写」只能靠约定与文档（缺口，见附录 B B-3） |
| 5 | 泛型 / 模板 | 本版本不做；内置容器由 `array` / `string` 提供（§2.6） |
| 6 | 运算符重载 | §1.6 已排除；内容相等用普通成员函数（§6.5 [15]） |
| 7 | 析构函数 / `delete` / 手动释放 | §6.5 [13]；需要释放外部资源时用显式 `close()` 成员函数 |
| 8 | 向下转换（基类 → 派生类） | 需要 RTTI 与运行时检查；替代：把差异做成 `override` 的成员函数（多态） |
| 9 | 隐式拷贝 / 拷贝赋值 | §6.5 [14]：引用绑定是默认，复制必须显式构造 |
| 10 | 反射 / RTTI | 本语言没有运行时类型信息；`__to_string__` 是唯一的运行时类型相关钩子（§6.9） |
| 11 | 属性（property）/ getter-setter 语法糖 | 用普通成员函数 |
| 12 | 具名构造参数 / 默认参数 | 用重载构造函数（§6.4 [8]） |

### 6.13 类部分的未定项 `?` [class.tbd]

> 只列**本部分引入或遗留**、且不影响本部分条款可实现性的项；全局未定项仍见 `nova-spec.md` §9。

| # | 未定项 | 影响 | 现有可用假设 |
|---|---|---|---|
| 1 | `vptr` 的具体宽度与调用约定细节 | 跨平台 ABI、原生包互操作 | 取目标平台指针宽度（§6.11 [2]） |
| 2 | 垃圾回收的**具体算法与暂停策略**（追踪式的标记-清扫 / 复制 / 分代；或带循环收集的引用计数） | 运行时性能、暂停时间、元数据位置 | 只要求「**非移动** + 最终回收**不可达对象（含引用环）**」（§6.5 [13]）；**纯引用计数不满足** |
| 3 | `const` 成员与 `const &T` / `&T const` 的确切语义 | 成员函数的常量性 | 本部分只用了「`const` 字段必须有初值」这一最小含义（§6.3 [5]） |
| 4 | `__to_string__` 之外的钩子集合（如迭代、比较） | 库设计 | 本版本只有两个钩子（§6.9 [2]） |
| 5 | 类类型与 `array` / `string` 的统一程度（`array` 归结为 class 的落地细节） | 类型系统、内置接口 | §2.6 与 `nova-types.yaml` |
| 6 | 未初始化**局部**变量的默认值 | 与 §6.3 [4] 的字段规则是否一致 | 本部分只定了字段；局部变量见 `nova-spec.md` §9.1 第 6 项 |

### 6.14 语法汇总（类） `✔` [class.grammar]

> 仿 §8 的 BNF 覆盖要求，给出本部分的产生式。
> **公共产生式**（`identifier`、`type_spec`、`expr`、`block`、`param_list`、`arg_list`、`const_expr`、`qualified_name`、`function_decl` 等）**统一见附录 G**：那里逐条给出归属章节，并分
> 「**规范定义** / **外部引用** / **非规范提示**」三档标注。其中 `type_spec`、`expr`、`block`、`arg_list`
> 属**外部引用**——**本文件没有定义它们**，须由类型 / 表达式 / 语句三章补齐（附录 B-1 第 6 项）。
> 合并各章 EBNF 时，**同名产生式以定义处为准，不得各自改写**。
> 本文件与 `nova-spec.md` 一致、可直接使用的部分（关键字、运算符、字面量）不再重复。

```ebnf
class_decl        = "class" identifier inheritance? "{" member_group* "}" ";"? ;
inheritance       = "<-" access_specifier qualified_name ;      # 单继承（§6.6 [3]）
access_specifier  = "public" | "protected" | "private" ;

member_group      = access_specifier "{" member* "}" ;
member            = field_decl | method_decl | constructor_decl | static_member ;

field_decl        = "const"? identifier ":" type_spec ( "=" expr )? ";" ;
method_decl       = method_modifier* "function" identifier "(" param_list? ")" ( "->" type_spec )?
                    ( block | ";" ) ;
method_modifier   = "override" | "async" ;                     # static 另有产生式，见下
constructor_decl  = "function" "__constructor__" "(" param_list? ")" block ;  # 不得写返回类型

static_member     = "static" ( static_field | static_method ) ;
static_field      = "const"? identifier ":" type_spec "=" const_expr ";" ;
static_method     = method_modifier* "function" identifier "(" param_list? ")"
                    ( "->" type_spec )? ( block | ";" ) ;

super_call        = "super" "." "__constructor__" "(" arg_list? ")" ";" ;
super_access      = "super" "." identifier ;
self_access       = "self" "." identifier ;

# 类作用域限定名：静态成员访问，以及类外成员函数定义（§6.4 [1]）
class_scope_name  = qualified_name "::" identifier ;

# 类名作为被调用者 = 构造调用（**没有** new / delete，§6.5 [3]）
construct_expr    = qualified_name "(" arg_list? ")" ;

# 钩子名（保留标识符，§6.9）
hook_name         = "__" identifier "__" ;
```

> **注（产生式与语义的对应关系）**
> 1. **字段声明**以 `;` 结尾；**以块结尾**的 `method_decl` / `constructor_decl` / `static_method`
>    定义之后**不加** `;`；以 `;` 结尾的成员函数是「只声明」（§6.4 [1]）。
> 2. **`identifier` 不得取 `__constructor__`**：构造函数一律用 `constructor_decl`（无返回类型）；
>    写成 `function __constructor__(...) -> T` 属**格式错误**（§6.5 [1]）。
> 3. 修饰符的合法组合由 `method_modifier*` 表达：`override`、`async`、两者同时（`override async function`）；
>    `static` 是 `static_member` 的引导词，因此 `static async function` 合法（§8.5 [1]）。
>    但 **`static override` 是格式错误**——静态成员不参与重写（§6.7 [4]）；这类**语义**约束由条款给出，EBNF 只表达形状。
> 4. `hook_name` 说明除 `__constructor__` / `__to_string__` 外的 `__名字__` 均**格式错误**（§6.9 [1]）。
> 5. `async` 的语义（任务、`await`、生成器）见第 8 部分；本节的产生式只表达**语法形状**。

### 7.1 模块单元 `✔` [module.unit]

**[1]** 一个 `.nova` 源文件就是一个**模块**，也是 `nvc` 的一个**编译单元**。

**[2]** **模块名** = 文件名去掉 `.nova` 后缀。文件名**必须**是合法标识符（§1.2），否则为**格式错误**。
本语言**没有** `module` 关键字。

**[3]** 模块顶层**只允许**下列声明：

```
import 声明（§7.3）
类声明（§6）
函数声明/定义（§5.5）
type 类型别名（§5.5）
const 常量（初值必须是常量表达式）
以上声明加 private 修饰（§7.5）
```

顶层 `let` 可变变量、赋值、循环等**可执行语句**一律为**格式错误**。

> 注：模块顶层没有可变状态，运行时也就**没有模块初始化函数**——静态字段的初值也要求是常量表达式（§6.8 [2]）。
> 由此得到两个好处：不存在「静态初始化顺序」问题；循环 `import` 是安全的（§7.3 [7]）。

**[4]** 本语言**没有头文件**（`✗`）。跨模块所需的全部信息来自编译器产出的**导出元数据**（§7.7 [7]）。

**[5]** 可执行程序的**根模块**必须提供名为 `main` 的函数。`main` 的签名与退出码语义见 §8.2 [11] 与 §8.8。

**[6]** 模块名在**同一个包内必须唯一**；不同包中可以有同名模块，用限定名区分（§7.4）。

### 7.2 包与文件系统 `✔` [module.pkg]

**[1]** 一个**包**（package）是一个**目录**，目录名即包名，**必须**是合法标识符。

**[2]** 包内可以有子包，子包是子目录；包的**限定名**用 `::` 连接，例如 `graphics::render`。

```
src/
  math/            # 包 math
    math.nova      # 模块 math
    sqrt.nova      # 模块 sqrt
  graphics/        # 包 graphics
    render/        # 子包 graphics::render
      draw.nova
  app.nova         # 根包（当前项目）的模块 app
```

**[3]** 包的**搜索根**由项目清单（§7.7 [2]）指定：本项目源码根与已解析的依赖包目录。
裸的包名（如 `math`）在搜索根下查找同名目录。

**[4]** **包作用域** = 该包内所有模块**导出**的顶层名字的并集。因此 `math::sqrt` 可以解析到
`math` 包中某个模块导出的函数 `sqrt`。

**[5]** 若包作用域中出现同名冲突（两个模块导出同名顶层名字），则**该名字的裸限定访问是格式错误**，
**必须**用 `包::模块::名字` 消歧。

**[6]** 同一包内，**模块名与子包名不得与该包任何模块导出的顶层名字同名**；违反者为**格式错误**。

> 注：没有这条，`包::名字` 会有两种解释（「包作用域里的导出名字」与「子包/模块名」）。
> 禁止同名让 `包::名字` 只有一种解释；这与 §7.4 [6]「歧义必须显式消解」同一取向。

**[7]** 同一包内，模块之间**不需要** `import`：直接用 `模块名::名字` 访问（§7.4）。

**[8]** 根包的模块（`src/app.nova` 这类不在任何子目录中的模块）之间同样遵循 [7]。

### 7.3 导入 `✔` [module.import]

**[1]** 两种 `import` 形式：

```nova
import math;              # ① 引入包：使用 math::名字 限定访问
import math::numeric;     # ② 引入模块：把 numeric 的导出顶层名字作为裸名引入本模块
```

**[2]** 所有 `import` **必须**出现在模块的**最前面**（在任何其它声明之前）。书写顺序不影响解析结果
（模块采用两遍扫描，§6.1 [4]），但违反位置要求为**格式错误**。

> 注：「顺序无关」与「位置必须在最前」不矛盾：前者说的是**解析结果**（`import a; import b;` 与
> `import b; import a;` 等价，且模块内声明与 `import` 的先后不影响谁可见）；后者是**书写格式要求**，
> 目的是让「这个模块依赖谁」在文件开头一眼可见。

**[3]** `import 包;` 只让**包名可解析**，**不**引入任何裸名。访问该包的成员必须写限定名 `包::名字`
（`math::sqrt(...)`）。

**[4]** `import 包::模块;` 把该模块**导出**的顶层名字以**裸名**引入本模块作用域。

**[5]** 名字冲突规则（**必须**诊断）：

| 冲突情形 | 结果 |
|---|---|
| 与**本模块已声明的**顶层名字同名 | **格式错误**，要求改用限定名或改名 |
| 与**另一个 `import 包::模块;`** 引入的名字同名 | **格式错误**，要求改用 `包::模块::名字` 限定 |
| 与 `uni` 的预导入名字同名 | **合法**：本模块声明与 import 的优先级高于 `uni`，`uni` 的名字被遮蔽 |

**[6]** 重复 `import` 同一目标是**幂等**的：写两次与写一次相同。

**[7]** **循环 import 合法**。因为 `import` 只影响名字可见性，不产生初始化代码（§7.1 [3]），
所以互相 `import` 的两个包不存在初始化顺序问题。

**[8]** `import` 解析失败（找不到包或模块）为**格式错误**，由 `nvc` 在编译期诊断——不是链接期错误。

**[9]** **没有传递可见性**：若 `a.nova` 导入了包 `b`，而 `b` 导入了包 `c`，则 `a` **不能**直接使用 `c::...`
（除非 `a` 自己也 `import c;`）。

> 注：这条规则让「一个模块能看见什么」完全由本文件开头的几行 `import` 决定，可读性与可分析性都更好。

**[10]** `import uni;` 合法，等价于无操作——`uni` 已自动可见（§7.6 [1]）。

**[11]** **不提供**导入别名（本语言没有 `as` 关键字），也**不提供**对单个函数/类的选择性导入。
需要消歧时一律写限定名。

### 7.4 名字解析与 `::` `✔` [module.name]

**[1]** `::` 是**路径解析运算符**，优先级最高（§1.6），左结合：`a::b.c` 解析为 `(a::b).c`，
`a::b::c` 解析为 `(a::b)::c`。

**[2]** `::` 的左操作数只能是**包名**、**模块名**或**类名**；右操作数只能是**名字**。
右操作数是表达式（如 `obj::x`）为**格式错误**：对象成员一律用 `.`。

**[3]** 合法的限定名形式：

| 形式 | 含义 | 前提 |
|---|---|---|
| `名字` | 本模块顶层名字、局部名、类成员 | — |
| `模块名::名字` | 同包内另一个模块的导出名字 | §7.6 例外见下 |
| `包名::名字` | 依赖包中被唯一解析到的导出名字 | 已 `import 包名;`（`uni` 除外） |
| `包名::模块名::名字` | 依赖包中某个模块的导出名字（消歧形式） | 同上 |
| `类名::静态成员` | 类的静态字段/静态函数（§6.8） | 类可见 |
| `包名::类名::静态成员` | 全限定形式 | 同上 |

**[4]** **裸名的解析顺序**（值上下文；类型上下文同序，只是只匹配类型名）：

```
1. 局部作用域（由内向外）：局部 let、形参、循环变量
2. 本类及其基类的成员（若在成员函数体内，§6.4 [3]）
3. 本模块的顶层声明
4. import 包::模块 引入的裸名（§7.3 [4]）
5. uni 的预导入名字（§7.6）
6. 全部未命中 → 格式错误
```

命中的第一个优先，即「**最近者胜**」；被遮蔽的名字**总是**可以用限定名显式访问
（字段用 `self.`，基类成员用 `super.`，模块名字用 `模块名::`，`uni` 用 `uni::`）。

**[5]** **不允许**前导 `::`（没有「全局作用域前缀」这种写法），`::sqrt(x)` 为**格式错误**。
被遮蔽的 `uni` 名字用 `uni::名字` 访问。

**[6]** 任何在编译期无法唯一确定的名字都是**格式错误**（歧义必须显式消解，不采用「就近猜」）。

**[7]** 名字解析**完全在编译期**完成，结果为静态绑定；本语言没有运行时的名字查找（没有反射，§6.12 [10]）。

### 7.5 模块级可见性 `✔` [module.vis]

**[1]** 模块的顶层声明**默认导出**（对其它模块可见）。

**[2]** 顶层声明前**可以**写 `private`，表示该名字**只在本模块内可见**：

```nova
private function helper(x: int) -> int { return x + 1; }

function api(x: int) -> int { return helper(x); }     # 导出
```

**[3]** 顶层声明前写 `public` 或 `protected` 为**格式错误**（模块层没有继承关系，这两个级别无意义）。

**[4]** **模块私有的名字不得出现在导出接口中**：它**不得**作为导出函数/成员函数的参数类型或返回类型，
**不得**作为导出类的基类，**不得**作为导出类的 `public` / `protected` 成员的类型。
违反者为**格式错误**。

> 注：这条是「无头文件」能够成立的关键——导出接口只依赖同样导出的名字，`nvld` 才能只靠符号表完成链接。

**[5]** 模块级可见性与类成员访问级别**正交**：先要求类本身可见，再按 §6.2 检查成员访问级别（§6.10 [1]）。

**[6]** 访问检查在**编译期**完成；跨模块访问 `private` 顶层名字为**格式错误**。

**[7]** 本语言**没有** `export` / `extern` 关键字（§1.4 已排除），也**没有**宏与条件编译。

### 7.6 标准包 `uni` `✔` [module.uni]

**[1]** `uni` 是**唯一预导入**的包：它的导出顶层名字在**每个**模块中都**可以裸名使用**，不需要 `import`。

**[2]** `uni` 的预导入名字可以**被遮蔽**（§7.3 [5]）；被遮蔽后用 `uni::名字` 显式访问。

**[3]** 本部分规定 `uni` 中具有**语言级语义**的入口（其余接口见《标准库》部分）：

| 名字 | 语义 |
|---|---|
| `range(a, b)` | 迭代生成器：左闭右开 `[a, b)`，步长 `1`。用于 §5.3 的 `for x in range(...)` |
| `range(a, b, j)` | 迭代生成器：左闭右开 `[a, b)`，步长 `j`（`j <> 0`） |
| `print(fmt, args...)` | 按 `{}` 占位格式化输出 |
| `println(fmt, args...)` | 同 `print`，末尾追加换行；`println()` 只输出换行 |
| `input(targets...)` | 从默认输入读取并**写入**作为实参的变量（实参必须是可赋值的位置） |

```nova
import math;                             # 依赖包必须显式 import（§7.3 [3]）

function roots(a: float, b: float, c: float, n: int) -> void {
    let d = math::sqrt(b * b - 4 * a * c);
    for i in range(0, n - 1) { }         # sort.nova / hanoi.nova 的既有写法：range 用于迭代
    println("d = {}", d);                # uni 预导入：无需 import，也无需 std::
}
```

> 注：`format` **不是** `uni` 的顶层入口，而是 `string` 类型的方法（`point.nova` 里的 `s.format("({}, {})", x, y)`），
> 其完整接口属《标准库》与 §2.6 的 `nova-types.yaml`；它遵守与 `print` / `println` 相同的 `{}` 占位规则（§6.9 [3]）。

**[4]** `range` 的 `for` 迭代语义：从左端开始，每轮取当前值后加上步长，直到**不满足** `< 右端`（步长为正时）
为止；`for` 的循环变量在循环体内是**只读**的副本。

**[5]** 除 `uni` 之外**不得**再有任何预导入包；其他包（如 `math`）一律显式 `import`（§7.3 [1]）。

> 注：`math` 与 `uni` 平级、且 `math` 需要 import，是 `nova-spec.md` §7 已定结论；本部分把它固化为
> 「唯一预导入包」的可见性规则，并销掉「`uni` 如何组织」这一未定项中与**可见性**有关的部分
> （`uni` 内部的模块划分仍属《标准库》部分）。

### 7.7 包管理器 `nvp` 与构建 `✔` [module.nvp]

**[1]** 工具链固定为：编译器 `nvc`、链接器 `nvld`、包管理器 `nvp`（`nova-spec.md` §7）。

**[2]** 项目由清单文件 **`nvp.toml`** 描述（新增定义）：

```toml
name    = "app"
version = "0.1.0"
nova    = "0.4"                  # 目标语言/ABI 版本
src     = "src"                  # 源码根，包在此目录下查找

[deps]
math    = "1.2"                  # 依赖包与版本约束
image   = { path = "../image" }   # 本地路径依赖

[native]
libpng  = { source = "native/libpng", abi = "0.4" }   # 原生包（§7.8）
```

**[3]** 依赖解析结果写入锁文件 **`nvp.lock`**：每个依赖的精确版本、来源与内容校验和。
`nvp` **必须**保证「清单 + 锁文件相同 ⇒ 解析出的依赖集合与内容相同」（可复现构建）。

**[4]** 命令：

| 命令 | 作用 |
|---|---|
| `nvp up` | 下载/更新依赖**源码**（已定结论） |
| `nvp add <包> [版本]` | 添加依赖并更新清单与锁文件 |
| `nvp remove <包>` | 移除依赖 |
| `nvp build` | 编译本包与依赖，产出可执行文件或库 |
| `nvp run [参数]` | `build` 后运行 |
| `nvp clean` | 清理构建产物（不删依赖源码） |
| `nvp list` | 列出已解析依赖及其版本 |

**[5]** 依赖源码与构建产物放在项目根的 `.nvp/` 目录下（具体布局**实现定义**）。

**[6]** 构建流水线：

```
解析 nvp.toml → nvp up（取依赖源码）
  → nvc 编译 Nova 模块（每个模块 → 一个目标文件 + 导出元数据）
  → 系统 C++ 编译器现场编译原生包源码（已定：包用 C++ 写，下载源码现场编译）
  → nvld 链接全部目标文件（链接期引入，必须携带符号表，§2.2）
```

**[7]** 每个 Nova 模块的编译产出**必须**包含**导出元数据**（符号表），内容至少为：

- 导出名字及其**修饰后符号名**（§7.8 [4]）；
- 函数与成员函数的**类型签名**（供跨模块重载解析与类型检查）；
- 类的**布局信息**（字段偏移、大小、对齐）与**方法表布局**（槽位 → 函数）；
- 目标**ABI 版本**（§7.8 [11]）。

**[8]** 若依赖图中出现同一包的两个**不兼容**版本，依赖解析**必须**失败并报错（构建错误），
不允许「同一 ABI 名字对应两个实现」。

### 7.8 原生包桥接契约 `✔` [module.native]

> 本节销掉「原生包桥接契约」这一未定项，把「包用 C++ 写、`nvp` 现场编译」这条已定结论补成可实现的契约。

**[1]** **原生包**是用 **C++** 编写的包（与编译器同语言）。原生包由 `nvp` 下载源码并**现场编译**为
目标文件/静态库，再由 `nvld` 与 Nova 目标文件一起链接。

**[2]** 每个原生包**必须**提供一个 **Nova 接口文件** `<模块名>.novai`：用 Nova 语法书写的**纯声明**
（无函数体），声明该模块对 Nova 侧呈现的顶层名字。

```nova
# math.novai —— 原生包的 Nova 视图（只有签名）
function sqrt(x: float) -> float;
function pow(x: float, y: float) -> float;

class complex {
    public {
        re: float;
        im: float;
        function norm() -> float;
    }
}
```

**[3]** 接口文件的内容由**受限产生式**给出（附录 G-2 的 `native_iface` / `native_function_decl` /
`native_class_decl` / `native_member` 系列）：只允许函数声明、类声明（字段、成员函数、**构造函数**、
**静态成员**）、`type` 别名、`const` 常量。

接口文件的**语法**本身就不接受下列内容，因此 `.novai` 校验**不需要**「先按完整类语法接受、
再在后处理阶段拒绝」——各实现的诊断位置一致：

| 在 `.novai` 中 | 结果 | 理由 |
|---|---|---|
| 函数体 / 成员函数体 / 构造函数体 | **语法错误** | 实现由 C++ 侧提供 |
| 字段初值 | **语法错误** | 字段存储与初始化由 C++ 侧负责 |
| `const` 字段 | **语法错误** | 跨边界无法保证「构造后不可变」（C++ 侧可任意改写）；需要只读语义时用**只读的成员函数**（getter） |
| `async` 函数或异步成员函数 | **语法错误** | 原生函数不得异步（[9]、§8.7 [3]）；受限产生式用的是 `native_method_modifier = "override"`，**不含 `async`** |
| 静态字段**带初值** | **语法错误** | 存储由 C++ 侧提供（见下） |
| 静态字段的类型为 `&T` / `string` / `array` | **语法错误**（它们不是 `native_static_type` 的成员） | 长期存储的语义未闭合：引用只在调用期间有效（[7]）；GC 对象的长期持有需要 root 登记与写屏障，而本版本没有这些机制 |
| 静态字段的类型（**展开别名后**）是**类类型或引用**，例如 `static obj: Widget;`、`type Ref = &Widget; static r: Ref;` | **格式错误**（语义检查，非语法错误） | 静态字段**只能**是 `bool` / `char` / `int` / `float`；类型别名照常展开后再判定（附录 G-2 注 7） |
| 实例字段的类型（**展开别名后**）是**引用**，例如 `type Ref = &Widget; r: Ref;` | **格式错误**（语义检查） | 实例字段只能是值类型或类类型，不得是 `&T`（见本节末「实例字段的类型」） |
| 用普通方法产生式写 `__constructor__`（带返回类型、加修饰符、或写成静态） | **语法错误** | 构造函数只能用 `native_constructor_decl`（附录 G-2 注 6） |
| 顶层语句、未导出的名字 | 语法 / 语义错误 | 接口文件是纯声明（由 `nvp` / `nvc` 校验） |

**构造入口**：`native_constructor_decl` 让原生类可以按 §7.8 [7] 表达「由 C++ 侧创建、交给 Nova 运行时管理」
的构造入口。构造函数**可以重载**（多个 `native_constructor_decl`，与 §6.5 [2] 一致），
**不写返回类型**、**不占方法表槽位**（§6.11 [7]）、**不得**加修饰符（含 `override` 与 `async`）。

**静态成员的初始化与符号提供方**：静态字段的**存储属于原生库**，接口文件只声明它的名字与类型，
因此 `.novai` 里没有初值的位置；Nova 侧**不得**假设其初值可在编译期求值。跨边界访问按 [4] 的
`_NVG` 规则使用 C++ 侧提供的符号。

**`_NVG` 静态字段的存储 ABI**（[4] 只给了名字规则，这里补齐读写约定）：

```
符号含义  _NVG… 是该字段的**本体**（对象本身），不是指向它的指针；Nova 侧通过该符号的**地址**读写。
宽度/对齐 按 §2.6：bool 1/1、char 1/1、int 4/4、float 8/8；C++ 侧用等价类型声明
          （bool / char / int32_t / double）。
初值      由 C++ 侧的静态初始化提供；Nova 侧不得假设初始化顺序，也不得假设其值可在编译期求值
          （§7.1 [3]：模块没有初始化代码）。Nova 侧的第一次访问最早发生在 main 开始之后，
          此时 C++ 侧的静态初始化已经结束；同一翻译单元内的初始化顺序问题由原生包负责。
并发      Nova 侧只按 §8.1 [5] 的内存模型访问；原生包若在别的线程改同一字段，本规范不作保证。
重复符号  同一个 `_NVG…` 符号只能由一个原生包提供；多个包声明同一「包::模块::[类::]名字」组合，
          在链接期表现为**重复符号**，是**链接错误**（不是未定义行为）。
```

**实例字段的类型**：`native_field_decl` 的类型可以是值类型或类类型（`native_field_type`），
但**不得**是引用 `&T`。**类型别名照常展开后再判定**（与 [4] 的别名展开一致）：
`type Ref = &Widget;` 后写 `r: Ref;` 为**格式错误**（展开后是引用）。

若该类要**按值**跨边界传递（[6] 的「无基类且无可分派成员函数」一行），
则其**所有**字段**必须**是值类型——因为 C++ 侧要声明等价 `struct`，而 `string` / `array` / 类类型的
内部表示尚未定稿（`nova-spec.md` §9.2 第 3 项）。

**例（合法的 `.novai`）：**

```nova
# math.novai —— 原生包的 Nova 视图（只有签名；包 math、模块 math）
type Scalar = float;

const PI: float = 3.141592653589793;

function sqrt(x: Scalar) -> float;
function pow(x: float, y: float) -> float;

class complex {
    public {
        re: float;
        im: float;

        function __constructor__(re: float, im: float);      # 构造入口（C++ 侧创建）
        function __constructor__(other: &complex);           # 重载：拷贝构造
        function norm() -> float;                            # 成员函数
        function __to_string__() -> string;                  # 钩子：无基类声明，故不写 override
        static function zero() -> complex;                   # 静态成员函数
    }

    private {
        static calls: int;                                   # 静态字段：存储由 C++ 侧提供（_NVG 符号）
        static scale: Scalar;                                # 合法：别名展开为 float（附录 G-2 注 7）
    }
}

class shape {
    public {
        function __constructor__();
        function area() -> float;
    }
}

class circle <- public shape {
    public {
        function __constructor__(r: float);
        override function area() -> float;                   # 重写：唯一允许出现在 .novai 的修饰符
    }
}
```

**反例（下列写法在 `.novai` 中一律是语法错误；按**位置**分组，避免误读）：**

顶层片段：

```nova
function f() -> int { return 1; }        # 函数体
async function g() -> int;               # 异步函数
```

类成员片段（放在某个访问组 `public { ... }` 内）：

```nova
x: float = 0.0;                          # 字段初值
const k: float = 1.0;                    # const 字段（注意：顶层的 const 是合法的，见正例）
async function h() -> void;              # 异步成员函数
static total: int = 0;                   # 静态字段带初值
static r: &Widget;                       # 静态字段不得是引用（语法）
static text: string;                     # 静态字段不得是 string（语法）
static data: array[int | 16];            # 静态字段不得是 array（语法）
override async function m() -> void;     # async 非法（override 本身合法）
function __constructor__(x: int) -> int; # 构造函数不得带返回类型
override function __constructor__(x: int);   # 构造函数不得加修饰符
static function __constructor__();       # 构造函数不是静态成员
```

别名展开后的**语义**检查（下面这段里的两个字段都是**格式错误**，而不是语法错误）：

```nova
type Ref = &Widget;                      # 顶层：别名本身合法

class w {
    public {
        static r: Ref;                   # 格式错误：别名展开后是引用（静态字段必须是值类型）
        f: Ref;                          # 格式错误：实例字段不得是引用
    }
}
```

必须**全部接受**；下表每行必须按注明的**阶段与理由**拒绝——注意区分**语法错误**（parser 阶段）与
**格式错误**（语义检查阶段）。**用例计数：1 个正例块 + 17 个反例 = 18 个用例，对应 17 行表格**
（正例块与每个反例各占一行，无合并行）：

**[4]** **名字修饰（name mangling）规则**（Nova 侧与 C++ 侧必须一致）：

```
模块级函数 : _NV enc(包) enc(模块) enc(名字) "_" 参数编码 "E"
成员函数   : _NV enc(包) enc(模块) enc(类名) enc(名字) "_" 参数编码 "E"
静态字段   : _NVG enc(包) enc(模块) [enc(类名)] enc(名字)
异步函数   : 在参数编码前加 "A"        # async 参与修饰，见 §8.7 [2]

enc(s)     : 十进制字节长度 + s        # 长度前缀，消除歧义
参数编码   : 依次拼接各参数的类型码，无参数时为空
类型码     : v=void  b=bool  c=char  i=int  f=float
             s=string  a=array  R<T>=&T（引用）  C<enc(限定名)>=类类型
```

> 注：`enc` 用长度前缀而不只是下划线连接，是为了让 `a_b` 与 `a` 加 `b` 不会撞名；
> 类型码进符号名，使**重载**（§6.4 [8]）在链接层可区分。

**签名 → 符号名的补充规则**（把 [4] 补成可实现的完整规则）：

| 项 | 规定 | 理由 |
|---|---|---|
| **返回类型** | **不**进入符号名 | 本语言不允许仅返回类型不同的重载（§6.4 [8]），符号名只需「限定名 + 参数类型」 |
| **`type` 别名** | **必须展开**到基类型后再编码 | `type MyInt = int;` 与 `int` 产生同一符号名 |
| **`array`** | 只编码为 `a`；**维度与长度不进入符号名** | 跨模块类型检查依据导出元数据里的完整签名（§7.7 [7]）；`array[int \| 9]` 与 `array[int \| 10]` 的区分属**类型检查层**，不是链接层 |
| **`const &T` / `&T const`** | 编码**相同**（同为 `R<T>`） | 两者确切语义未定（`nova-spec.md` §9.1 第 1 项）；将来若区分即为 **ABI 变更**（§7.8 [11]） |
| **类外成员函数定义** | 符号名与类内定义**必须相同**（由「包 + 模块 + 类名 + 函数名」决定） | §6.4 [1] 允许 `类名::函数名` 在类外定义，链接结果不得依赖定义位置 |
| **构造函数** | 按成员函数编码，名字段为 `__constructor__` | 与 §6.11 的方法表无关，构造函数不占槽位 |
| **无法编码的类型** | `nvc` **必须**诊断，**不得**静默生成可能冲突的名字 | 将来新增类型构造时防止符号名撞车 |

**名字修饰测试向量**（`nvld` 与 C++ 侧必须得到同一结果；下表的包为 `app`、模块为 `main`）：

| 声明 | 期望符号名 |
|---|---|
| `function f() -> void` | `_NV3app4main1f_E` |
| `function g(a: int, b: float) -> int` | `_NV3app4main1g_ifE` |
| `function h(p: &int) -> void` | `_NV3app4main1h_RiE` |
| `type MyInt = int;` 后 `function k(a: MyInt) -> void` | `_NV3app4main1k_iE`（别名**展开**） |
| `function m(a: array[int \| 9]) -> void` | `_NV3app4main1m_aE`（与 `array[int \| 10]` **同码**） |
| `class point { public { function norm() -> float } }` | `_NV3app4main5point4norm_E` |
| `async function c(a: int) -> int` | `_NV3app4main1c_AiE` |
| `function counter::bump() -> int`（类外定义） | `_NV3app4main7counter4bump_E`（与类内定义同码） |

**[5]** **调用约定**：值类型（`bool` / `char` / `int` / `float`）按目标平台的 C 调用约定传值；
`&T`、类类型与 `string` / `array` 按**对象地址**传递（引用语义 + 非移动对象，§6.5 [13]）。
返回 `void` 的函数返回 `none`。

**[6]** **可跨边界传递的类型**：

| 类型 | 能否跨边界 | 约束 |
|---|---|---|
| `bool` `char` `int` `float` | 可以 | 按 C 调用约定 |
| `&T` | 可以 | 调用期间有效 |
| `string` `array` | 可以 | 作为**不透明引用**；C++ 侧**不得**假设内部存储布局（`nova-spec.md` §9.2 第 3 项未定） |
| 无基类、且没有任何可分派成员函数（`public`/`protected` 非 `static` 成员函数）的类 | 可以**按值**传递 | 布局 = `vptr` 槽位 + 字段区（§6.11 [1]）；C++ 侧必须按目标 ABI 的 `vptr` 宽度声明等价 `struct`（首成员为指针宽度的占位槽），**不得**读写该槽位。不愿依赖 `vptr` 宽度时，一律按不透明句柄处理 |
| 其余类（含 `vptr` 或继承） | 只能作为**不透明句柄** | C++ 侧不得直接读写字段，只能通过接口文件中声明的成员函数访问 |

**[7]** **内存所有权**：Nova 侧传入的对象引用在**本次调用期间**有效。C++ 侧**不得**把该引用
保存在比调用更长的生存期里（对象可能被垃圾回收）；需要长期持有**必须**自行复制到 C++ 管理的存储中。
C++ 侧创建的对象若交给 Nova，**必须**通过接口文件声明的构造入口，并让其由 Nova 运行时管理。

**[8]** **错误传播**：本语言没有异常。C++ 侧**不得**让 C++ 异常跨越原生边界——跨边界传播的异常为
**未定义行为**。失败**必须**通过返回值或输出参数（`&T`）表达。

**[9]** 原生函数**不能**声明为 `async`（跨边界无法表达任务，§8.7 [3]）：在 `.novai` 中写 `async`
是**语法错误**（受限产生式里的 `native_method_modifier` 只含 `"override"`，静态成员函数更是完全不带修饰符，见 [3]）。
Nova 侧对原生函数的调用是**可能阻塞**的（§8.6 [4]）。

**[10]** 原生包的符号表由接口文件与 C++ 编译产物共同提供，`nvld` 据此完成链接；缺失符号为**链接错误**。

**[11]** **ABI 版本**：原生包**必须**在 `nvp.toml` 中声明它针对的 Nova ABI 版本；
ABI 版本不匹配的包**不得**参与链接（构建错误）。ABI 版本覆盖：名字修饰规则（[4]）、
类布局与方法表布局规则（§6.11）、`vptr` 宽度（§6.11 [2]）、异步任务表示（§8.7 [4]）。

**[12]** **安全边界**：越过原生边界后，Nova 的类型安全与内存安全保证**不再成立**
（原生包不受本规范的检查约束）。因此原生包必须在清单中显式标注（`[native]` 段），
`nvp` 必须在构建输出中列出所有原生依赖。

### 8.1 执行模型与内存模型 `✔` [async.model]

**[1]** 一个 Nova 程序的执行由一个或多个**任务**（task）组成。任务是可挂起、可恢复的执行流。

**[2]** 运行时提供一个**任务调度器**。程序启动时存在一个初始任务，它执行入口函数 `main`（§8.8）。

**[3]** **协作式并发**：在任一时刻**至多有一个**任务在运行。任务只在**切换点**（§8.6 [1]）让出控制权，
其余时间不会被抢占。

**[4]** 本语言**不提供并行**（parallelism）：没有多线程语义，没有原子类型，没有锁。
由于任一时刻至多一个任务在运行（[3]），本执行模型**不会产生并行数据竞争**——两个任务不可能真正同时
访问同一存储单元。但这**不等于**程序自动正确：

- **逻辑竞态仍然可能**：两个任务可以在不同切换点之间以错误的顺序读写同一对象，结果依赖调度顺序；
- 语言**不检查**逻辑竞态，也不提供锁或原子操作；程序应把「一组必须一起生效的修改」放在
  两个切换点之间完成（该区间相对其它任务是原子的，§8.6 [3]）；
- 原生包若越过边界后自行创建线程，本规范**不作任何保证**（§7.8 [12]）。

> 注：「并发但不并行」是本版本最重要的可靠性决定：没有原子类型与锁的语言如果允许真并行，
> 就必然存在无法表达、也无法检查的数据竞争；与其先引入一整套并发同步机制，不如先把
> 「任务不会同时运行」这一条做扎实，并把逻辑竞态留给程序员用「切换点之间是原子的」来管理。

**[5]** **内存模型**：

- 所有任务共享同一份内存视图；**同一任务内**的求值按程序顺序发生；
- **切换点是唯一的跨任务同步边**：若任务 A 在切换点 `p` 让出、任务 B 随后被调度运行，
  则 A 在 `p` 之前的全部写，对 B 在 `p` 之后的全部读**可见**（happens-before）；
- 切换点清单见 §8.6 [2]（**含异步调用点 ④**）；两个切换点之间没有跨任务的顺序保证；
- 由于不存在并行，程序**不需要**内存屏障；语言也**不提供** `volatile`、原子操作或内存序标注。

**[6]** **垃圾回收与挂起任务**：被挂起任务的栈与其中保存的局部变量**必须**被视为可达根（GC root）。
实现**必须**保证挂起任务的局部对象不会被回收。

**[7]** 调度器**不保证公平性**，也不保证任务的相对推进速度。一段不含切换点的死循环
（如 `while true { }`）会**永久**占住调度器。

**[8]** 本版本**没有**任务优先级、**没有**任务取消、**没有**超时机制。

### 8.2 异步函数与任务 `✔` [async.task]

**[1]** `async` 写在 `function` 之前，声明一个**异步函数**：

```nova
async function fetch_sum(a: int, b: int) -> int {
    let x = await compute(a);
    let y = await compute(b);
    return x + y;
}
```

`async` 可以修饰模块级函数、成员函数与静态成员函数。

**[2]** 异步函数的**返回类型注解表示结果类型**（`await` 得到的类型），不是任务类型。
省略 `-> T` 时结果类型为 `void`，此时 `await` 的值是 `none`。

**[3]** 调用异步函数**不阻塞调用者**：该调用创建一个**任务**并交给调度器，然后立即求值为该任务的**任务句柄**。

**[4]** 一次异步调用的事件顺序**固定**如下（**次序是规范性的**，**节奏是实现定义的**）：

```
① 在调用者上下文中求值全部实参（实参的副作用在此完成）；
② 创建任务，并把它登记到调用点所在的所有者块（见 [7]）；
③ 此后新任务才可能被推进，推进到它的第一个切换点为止——异步调用点是切换点（§8.6 [2] ④）；
④ 调用者从调用点继续执行下一条语句。
```

任务在 ③ 中被推进多少（立即跑到第一个切换点，还是留到调度器下次选择它）属**实现定义**；
程序**不得**依赖推进量（§8.1 [7]），但**可以**依赖 ①→②→③→④ 的次序，以及 §8.1 [5] 的可见性规则。

**[5]** 任务句柄的静态类型记作 `Task⟨f⟩`（`f` 为被调用的异步函数），按函数**单态化**——
这是本语言在没有泛型的前提下表达「带结果类型的任务」的方式。

> 注：`Task⟨f⟩` 里的 `⟨ ⟩` **只是本规范的元语言记号**，不是语言符号（不在 §1.6 的运算符集里），
> 源程序中不出现；`Task⟨f⟩` 也**不可书写**（[6]）。

**[6]** `Task⟨f⟩` 类型**不可书写**：它**不得**出现在形参类型、返回类型、字段类型、`type` 别名或数组基类型中；
违反者为**格式错误**。因此任务句柄**只能**作为**局部变量**存在：不能跨函数传递、不能存入对象或数组。

```nova
async function demo() -> int {
    let t = fetch_sum(1, 2);        # 合法：let 自动推导出 Task⟨fetch_sum⟩
    let r = await t;                # 合法：r 为 int
    return r;
}
# function bad(t: Task<fetch_sum>) -> void { }   # 格式错误：任务类型不可书写
```

**[7]** **结构化并发**：任务归**创建它的作用域**所有。这里的**作用域**有确定含义：
指**词法块** `{ }`，以及**函数体**（函数体本身视为一个块）；**不是**调用帧，也不是运行时对象。

```
① 创建任务时，把它登记到**最近的词法块**（创建点若在函数体顶层，则登记到函数体）——称为它的所有者块；
② 一个任务**只属于一个**所有者块；
③ 控制流离开所有者块时（正常结束、return、break / continue 跳出该块等），运行时**等待**该块登记的、
   尚未结束的任务全部完成；
④ 已结束的登记项随即移除，所以同一个任务**不会被等待两次**：内层块退出时已等待过的任务，外层块不再重复等待；
⑤ 等待多个任务时的**顺序未规定**，程序**不得**依赖（与 §8.1 [7] 一致）；
⑥ 等待**不取消**任务：任务总是运行到完成或挂起（本版本无取消，§8.9 [2]）。
```

**[8]** 因此，异步调用可以直接作为语句（丢弃句柄）：

```nova
async function fan_out() -> void {
    compute(1);                 # 启动但暂不等待：句柄丢弃，任务仍归本作用域所有
    compute(2);                 # 同上，两个任务将并发推进
    let t = compute(3);
    let v = await t;            # 只等第三个
    # 函数返回前，运行时会等待前两个任务结束（[7]）
}
```

**[9]** `await` 一个**已完成**的任务立即得到其结果；同一个句柄**可以**多次 `await`，结果相同。

**[10]** **异步调用只能出现在异步函数体内**。在非异步函数中调用异步函数为**格式错误**。

> 注：本语言没有阻塞原语（没有 join/block_on），所以「同步函数里顺手启动一个后台任务」这种写法被禁止，
> 以避免隐式阻塞与不可预测的推进顺序。代价是异步会沿调用链传播，见 §8.9 [4]。

**[11]** `main` **可以**声明为异步函数：`async function main() -> int`。语义见 §8.8 [3]。
若 `main` 是普通函数，则程序按普通方式执行。

> 注：本条连带定稿了 `nova-spec.md` §9.1 第 5 项的一部分：`main` 无参、返回 `int`、返回值即进程退出码；
> 是否允许异步见 [11]。回填项见附录 C。

### 8.3 `await` `✔` [async.await]

**[1]** `await` 是**前缀运算符**，构成 `await 表达式`。因为一切皆表达式（§4.1），`await` 也是表达式，
其值是**被等待任务的结果**。

**[2]** `await` 的操作数**必须**是任务类型的表达式（通常是一次异步调用，或由 `let` 推导出的任务变量）。
对非任务类型使用 `await` 为**格式错误**。

**[3]** `await` **只能**出现在异步函数体内（含生成器体与异步成员函数体）。出现在普通函数、构造函数的
函数体中为**格式错误**。

**[4]** `await` 的语义：

```
① 求值操作数（得到目标任务；若操作数是一次异步调用，则在此创建任务）
② 若目标任务尚未完成：当前任务挂起（这是一个切换点，§8.6 [2]），控制权交回调度器
③ 目标任务完成后，当前任务被唤醒，await 表达式的值 = 目标任务的结果
④ 若目标任务的结果类型是 void，await 表达式的值为 none
```

**[5]** `await` **不做错误传播**：本语言没有异常，`await` 不会「抛出」什么。
被等待函数的失败**必须**已经编码在它的**返回值**里（§8.9 [1]）。

**[6]** 求值顺序：操作数先求值，然后才挂起。因此 `await f(x)` 中 `x` 的副作用发生在挂起之前。

**[7]** 若被等待的任务**永远不会完成**（例如两个任务互相等待），当前任务将永远挂起——
程序挂起，本版本**没有**超时与死锁检测（§8.6 [6]）。

### 8.4 `yield` 与生成器 `✔` [async.gen]

**[1]** 函数体内出现 `yield` 的**异步函数**是一个**生成器**；不含 `yield` 的异步函数是任务函数（§8.2）。

**[2]** 生成器的**返回类型注解表示它产出的元素类型**（不是结果类型）。

**[3]** 调用生成器返回一个**流句柄**，其类型记作 `Stream⟨f⟩`，与任务句柄一样**不可书写**、只能由
`let` 推导为局部变量（§8.2 [6] 的规则同样适用）。

- 生成器调用产生的是 `Stream⟨f⟩`，**不是** `Task⟨f⟩`：生成器结束时**没有**可供 `await` 的最终值
  （返回类型注解已被用作元素类型，[2]），因此对生成器调用写 `await` 为**格式错误**。
- 生成器的**元素类型不得为 `void`**：`async function f() -> void { yield ...; }`
  （以及省略返回类型却含 `yield` 的函数）为**格式错误**——元素类型必须能安放 `yield` 的值。
- 生成器体**惰性启动**：只有在**第一次请求元素**时才开始执行；仅仅创建一个流句柄
  （例如 `let s = squares(3);`）**不产生**任何运行时执行状态。

**[4]** `yield 表达式;` 把表达式的值交给消费者，并**挂起**当前生成器，直到消费者请求下一个元素。
`yield` 必须带值（`yield;` 为**格式错误**，§8.12）；表达式本身是表达式，其值为 `none`
（本版本没有双向通道，消费者不能向生成器回传值）。

**[5]** 生成器的消费形式是 `for` 迭代：

```nova
async function squares(n: int) -> int {          # 元素类型是 int
    let i = 0;
    while i < n {
        yield i * i;
        i = i + 1;
    }
}

async function use_it() -> void {
    for s in squares(3) {                        # 取元素处是切换点
        println("{}", s);
    }
}
```

**[6]** `for 变量 in 流表达式 { }` 中，循环变量的类型是该流的元素类型。

**[7]** 迭代**异步流**的 `for` **必须**出现在异步函数体内（取下一个元素是一个切换点）。
迭代**同步序列**（`range(...)`）的普通 `for` 不受此限制（§5.3），也**不是**切换点。

> 注：这条区分是必要的：`sort.nova` 的 `select_sort` 是**普通函数**，里面用 `for i in range(0, n - 1)`。
> 如果把所有 `for ... in` 都当成异步迭代，既有示例就会全部非法。因此规范区分两类可迭代对象：
> **同步序列**（`range`，见 §7.6 [3]；是否包含 `array` 见 §8.11 第 4 项）与**异步流**（本节的生成器）。

**[8]** 生成器体执行到末尾（或执行 `return;`）即结束迭代。生成器体内 `return` **不得带值**
（`return 表达式;` 为**格式错误**）：返回类型注解已被用作**元素类型**（[2]），没有第二个位置安放结果值。

**[9]** **流的放弃**（abandonment）：当迭代没有走到耗尽、或流句柄不再被使用时，流被**放弃**。
下列任一路径都会导致放弃：

```
① for 循环用 break / 控制流跳出，提前结束迭代；
② 迭代所在的词法块被 return 或其它控制流离开；
③ 流句柄离开它的作用域，或被重新赋值（原句柄不再可达）；
④ 流句柄作为表达式语句被直接丢弃（例如 `squares(3);`）。
```

放弃的语义（**规范性**）：

```
a. 终止生成器：不再恢复其执行；已经交出的元素保持已交出的状态。
b. 终止前**等待**该生成器体内已创建且尚未结束的任务全部结束——生成器体的词法块被放弃时，
   同样适用结构化并发的 join 规则（§8.2 [7]）。
c. 随后回收生成器的挂起状态。本语言没有析构，生成器**没有**「清理代码」的保证（§6.9 [5]）。
d. 若流尚未启动（见 [3] 的惰性启动），放弃它不产生任何 join 与回收动作，只释放句柄本身。
e. 迭代**正常耗尽**（[8]）不是放弃：生成器已自然结束，句柄按 [10] 处理。
```

**[10]** 流是**一次性**的：已经耗尽的流再次迭代会立即结束（不报错）。

**[11]** 生成器体内**可以** `await`，因此可以在产出元素之间做并发。但**生成器句柄本身是 `Stream⟨f⟩`，
不是 `Task⟨f⟩`**（[3]）：它不能作为 `await` 的操作数，也不适用任务的结果类型规则；能等待的只是
生成器体**内部**创建的**任务**。这些任务归**生成器体的词法块**所有（§8.2 [7]）；句柄被放弃时按 [9] 处理。

**[12]** `yield` 出现在**非异步**函数体内为**格式错误**。

### 8.5 异步与类 `✔` [async.class]

**[1]** 成员函数与静态成员函数**可以**是 `async`；调用与等待规则同 §8.2、§8.3：

```nova
class loader {
    public {
        async function load(id: int) -> string { ... }
        static async function open(path: &string) -> loader { ... }
    }
}

async function use() -> void {
    let l = loader::open("a.txt");
    let inst = await l;
    let s = await inst.load(1);
}
```

**[2]** **构造函数不得是异步的**：`async function __constructor__(...)` 为**格式错误**。
构造函数必须在对象引用交给调用者之前同步完成（§6.5 [6]）。

**[3]** **重写要求 `async` 修饰一致**：若派生类成员函数重写基类的异步函数，它**必须**也是 `async`；
反之亦然。违反者为**格式错误**。同一作用域内仅 `async` 不同的同名同参数函数同样是**格式错误**
（`async` **不是**签名的一部分，不能靠它形成重载）。

**[4]** 钩子函数（§6.9）**不得**是 `async`：`__to_string__` 会在 `println` 的同步格式化过程中被调用。

**[5]** 异步成员函数同样走**动态分派**（§6.7）：`await obj.f()` 中的 `obj.f()` 调用按 `obj` 的动态类型
选择实现，然后等待它返回的任务。因此异步方法可以被重写、被多态调用。

**[6]** 任务句柄与流句柄**不能**作为类的字段类型（§8.2 [6]），因此类不能把「未完成的工作」保存为成员。

### 8.6 切换点、阻塞点与调度 `✔` [async.sched]

**[1]** **切换点**是任务可能让出控制权的程序点。切换点是本语言中**唯一**可观察到的任务交错位置。

**[2]** 切换点的完整清单：

```
① await 表达式（当目标任务尚未完成时）
② for 迭代异步流时取下一个元素（含循环开始与每次回边）
③ yield 表达式
④ 异步调用点：任务在此创建；实现可以让新任务在此推进到它的第一个切换点
```

**[3]** 不含切换点的代码段是**原子的**（相对其它任务）：包括所有**非 `async`** 的函数调用、所有 `range` 循环、
所有字段访问与算术运算。程序可以依赖这一点，无需额外同步。

> 注：异步调用点（[2] ④）之所以算切换点，是因为新任务可能在此开始执行。它推进到哪里由实现决定
> （§8.2 [4]），程序不得依赖具体时机——把「启动并发」与「等待结果」分开写（§8.2 [8]）才是可移植的用法。

**[4]** **阻塞点**：调用原生包函数（§7.8）时，本版本的实现**必须**把该调用当作**阻塞点**——
调用期间调度器**不推进**任何其它任务，整个程序停在该调用上，返回后继续。

> 注：这样规定是为了不破坏 [3] 的原子性承诺：语言没有原子类型与锁，如果允许原生调用与其它 Nova 任务
> 并行执行，共享对象的访问就不可控了。代价是阻塞式 I/O 会拖住整个程序（§8.9 [5]）。
> 扩展路径（本轮不做）：引入显式并行的原生调用标注 + 原子类型。

**[5]** 调度策略（就绪队列的组织、唤醒顺序、栈大小、是否分片）属**实现定义**，
但**必须**满足 [1]–[4] 的语义与 §8.2 [7] 的结构化并发语义。

**[6]** **死锁与饥饿**：任务互相等待时程序挂起；本版本没有死锁检测、没有超时、没有取消。
一个不含切换点的死循环同样会导致其它任务永不推进（§8.1 [7]）。

### 8.7 异步与 ABI、链接、原生包 `✔` [async.abi]

**[1]** 任务句柄与流句柄的运行时表示属**实现定义**，但**必须**满足：

- 句柄是对**不可移动的堆对象**的引用（§6.5 [13]）；
- 同一 ABI 版本下，任务与流的表示、创建与唤醒接口跨**模块**必须一致（属于 ABI 的一部分）。

**[2]** **名字修饰**：异步函数的符号名在参数编码前加 `A`（§7.8 [4]）：

```
async function compute(a: int) -> int      # 包 math、模块 math 中的 compute
  → _NV4math4math7compute_AiE
```

> 注：`enc("math") = "4math"`（4 字节 + 原名），包名与模块名各自独立编码；
> `_A` 是 `async` 标记（[2] 首句），`i` 是参数 `a: int` 的类型码，`E` 结束。

> 注：`async` 不参与语言的签名比较（§8.5 [3]），但显式写进符号名可以让 `nvld` 的符号表、
> 原生包接口与调试信息自解释，也避免「同步/异步调用约定不同却同名」的隐患。

**[3]** **原生包不得导出异步函数**（§7.8 [9]）：跨边界无法表达任务语义。
任务句柄与流句柄**不可能**出现在接口文件中（它们的类型不可书写，§8.2 [6]）。

**[4]** ABI 版本**必须**覆盖：任务/流的表示与调度器接口（[1]）、名字修饰规则（[2]）、
以及 §6.11 的对象布局（异步方法仍依赖方法表）。

**[5]** 跨模块 `await` 合法：只要被调用的异步函数按 §7.3 可见，即可在另一个模块中创建并等待其任务。

### 8.8 生命周期与程序退出 `✔` [async.life]

**[1]** 程序的**根任务**执行入口函数 `main`。

**[2]** 若 `main` 是**普通**函数：按 §5 的同步语义顺序执行；`main` 返回即程序退出，其返回值是进程退出码。
此时程序内**不能**调用异步函数（§8.2 [10]），因此没有任务被创建。

**[3]** 若 `main` 是**异步**函数 `async function main() -> int`：运行时启动调度器并驱动 `main` 任务，
直到它完成；`main` 任务的返回值是进程退出码。

**[4]** 由于结构化并发（§8.2 [7]），`main` 任务完成时，其作用域内创建的所有任务都已结束。
因此程序退出时**不存在**仍在运行的任务，也**不需要**「等待后台任务」的额外 API。

**[5]** 程序结束时，运行时回收堆对象（§6.5 [13]）。本语言**不保证**任何「确定的清理时机」：
没有析构函数（§6.9 [5]），生成器被放弃时的挂起状态也不会触发用户代码。

**[6]** 若 `main` 任务永远挂起（死锁），程序永不退出（§8.6 [6]）。

### 8.9 错误处理与本版本的固有限制 `✔` [async.limit]

**[1]** **错误模型**：本语言没有异常（`✗`，全局结论）。因此

- `await` 不会失败，也不会传播错误；
- 异步函数的失败**必须**通过**返回值**表达；手段取决于结果类型：
  - 结果类型是**值类型**（`bool` / `char` / `int` / `float`）：用**哨兵值**（如 `-1`）或状态编码；
  - 结果类型是**类类型**：**没有空值**可用（§6.3 [4]），必须用**输出参数 + `bool` 状态返回值**（§6.5 [12]）；
  - 结果类型是 `void`：只能靠输出参数表达失败。
  **不得**用 `none` 表示失败——`none` 是 `void` 的值（§1.5），对类类型非法，对 `void` 无意义（返回 `void` 本身就是正常完成）；
- 调用者**必须**显式检查返回值，没有 `try` / `catch` 这样的集中处理路径。

```nova
# 约定：负数表示失败（本语言没有异常，也没有可空类型）
async function read_int() -> int {
    let v = await read_raw_int();
    if v < 0 {
        return -1;
    }
    return v;
}

async function show() -> void {
    let v = await read_int();
    if v < 0 {
        println("read failed");          # 失败必须由调用者显式检查
    } else {
        println("v = {}", v);
    }
}
```

> 注：因为本语言没有泛型与可空类型（§1.5：`none` 是 `void` 的值，不是「空的可选值」），
> 「可能失败的异步读取」只能用返回状态值或输出参数的方式编码。
> 具体约定属《标准库》部分的接口设计（见 §8.11 第 5 项）。

**[2]** 本版本**不提供**：任务取消、超时、优先级、分离任务（detach）、任务组 API、
`await` 组合子（gather / select / race）。并发组合只能用「先启动、后依次 `await`」表达。

**[3]** **没有并行**：CPU 密集的任务无法利用多核（§8.1 [4]）。

**[4]** **函数着色**：只有异步函数能调用异步函数（§8.2 [10]），`async` 会沿调用链向上传播。
这是 `async` / `await` 模型的固有代价，C++、Rust、Kotlin、Python 同样存在。

**[5]** **原生调用阻塞整个调度器**（§8.6 [4]）：阻塞式 I/O 会拖住所有任务。

**[6]** **不保证公平性**：长时间不含切换点的计算会让其它任务饥饿（§8.1 [7]）。

| # | 限制 | 本节条款 | 可能的演进方向（非规范） |
|---|---|---|---|
| 1 | 无错误传播通道 | [1] | 引入 `Result` 风格的标准库类型，或引入可空类型 |
| 2 | 无取消/超时 | [2] | 引入协作式取消标记 + 取消点 |
| 3 | 无并行 | [3] | 引入显式并行构造 + 原子类型/锁 |
| 4 | 函数着色 | [4] | 引入隐式等待或对称协程 |
| 5 | 原生调用阻塞调度器 | [5] | 允许标注「可卸载」的原生调用 + 共享状态规则 |
| 6 | 无公平性保证 | [6] | 调度器加入时间片或循环回边检查 |

### 8.10 明确排除项 `✗` [async.excluded]

| # | 排除项 | 理由 / 替代 |
|---|---|---|
| 1 | 多线程 / 真并行 | §8.1 [4]；无原子类型与锁，并行必然引入不可检查的数据竞争 |

| 6 | 任务句柄作为一等值（可传参、可存字段） | §8.2 [6]；任务类型不可书写 |
| 7 | `Task[T]` 形式的泛型任务类型 | 本语言没有泛型（§6.12 [5]）；用单态化的 `Task⟨f⟩` 替代 |
| 8 | 非异步函数调用异步函数（隐式阻塞） | §8.2 [10] |
| 9 | 异步构造函数 / 异步钩子 | §8.5 [2] [4] |
| 10 | 原生包导出异步函数 | §8.7 [3] |

### 8.12 语法汇总（异步执行） `✔` [async.grammar]

> 类内与静态的异步成员函数**不另立产生式**：它们由 §6.14 的 `method_modifier`（含 `"async"`）覆盖，
> 即 `async function` / `override async function` / `static async function` 都在那里定义，避免两处产生式打架。
> 公共产生式（`expr`、`block`、`param_list`、`type_spec`、`identifier`、`range_call`）的归属与状态见**附录 G**
> 的归属表；其中 `expr`、`block`、`type_spec` 属**外部引用**（本文件未定义，须由对应章节补齐）。

```ebnf

yield_expr          = "yield" expr ";"                        # 仅允许出现在 async 函数体内；**必须带值**

stream_for          = "for" identifier "in" expr block ;      # expr 为 Stream⟨f⟩ 时是异步迭代（切换点）

# 说明（不是产生式）：
#   · 被调用者是 async 函数时，调用表达式的类型为 Task⟨f⟩；是生成器时为 Stream⟨f⟩。

#     它们**不可书写**（§8.2 [5][6]）：不得出现在 `type_spec` 能出现的位置。
#   · 生成器体内 `return` **不得带值**（§8.4 [8]）。
```
