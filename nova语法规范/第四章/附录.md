## 附录 F 合规性、实现自由度与未定义行为 `✔`

> 仿 C++ 标准的 conformance 条款：把「实现必须做什么」与「实现可以怎么选」分开列清，
> 便于 `nvc` / `nvld` / `nvp` 的实现者对照检查，也便于评审时判断「这算不算违规」。

### F-1 合规实现的要求

**[1]** 一个**合规的实现**：

```
① 必须接受所有符合本部分与 nova-spec.md 的程序（资源限制除外）；
② 对格式错误的程序必须给出诊断并拒绝翻译，不得「猜一个解释」放过去；
③ 对违反「必须 / 不得」的静态可判定情形，必须在编译期诊断（§6.2 [7]、§6.7 [2]、§7.5 [6] 等）；
④ 对标注未定义行为的程序不作任何保证；
⑤ 必须为每一个「实现定义」项选定确定行为，并在实现文档中记录该选择；
⑥ 不得为合法程序附加本规范未要求的可观察行为（例如：程序不得观察到任务的相对推进速度）。
```

**[2]** 实现**可以**提供文档化的**扩展**，但扩展**不得**改变合法程序的含义：
扩展只对本来格式错误的程序生效，或在语用层面提供额外能力（调试、优化提示）。

**[3]** 实现**必须**在文档中给出本文件涉及的「实现定义」项清单（见 F-2）与「未定义行为」清单（见 F-3）。

> （§6.14 / §7.11 / §8.12）还引用了属于**其它章节**的产生式。本附录把它们逐条列出并标状态，
> 以避免两种错误：把外部产生式当成已定义（**悬空引用**），或在本文件里给出与其它章节不一致的
> 简化定义（**伪语法**）。
>
> **三种标签**：
>
> | 标签 | 含义 | 能否作为实现依据 |
> |---|---|---|
> | **规范定义** | 本文件给出完整语法，其它章节必须遵守 | 能 |
> | **外部引用** | 不在本文件定义，由所注章节提供，本文件只按名字引用 | **不能**，须等该章节补齐 |
> | **非规范提示** | 仅为对照而给的形状提示，**不是**定义，可能与最终写法不同 | **不能** |
>
> **如实声明**：`expr` / `statement` / `block` / `type_spec` / `arg_list` 已由**第二章 2.12** 给出（G-1 标注为「规范定义」，2026-09-24 更新）；
> 本文件的 EBNF 与第二章合并后**可以**构造 parser。附录 B-1 第 6 项的阻塞状态随之解除，
> 剩余为附录 C 第 5 项的语法闭包检查。

### G-2 本文件规范定义的产生式

```ebnf
# —— 词法（§1）：与 nova-spec.md §1.2 逐字一致 ——
identifier          = ( letter | "_" | "$" ) { letter | digit | "_" | "$" } ;
letter              = "A".."Z" | "a".."z" ;                   # §1.1 ASCII 可打印字符集
digit               = "0".."9" ;

# —— 名字与作用域（本文件 §7.4 [3]、§6.14）——
qualified_name      = identifier { "::" identifier } ;
# class_scope_name 见 §6.14（类作用域限定名：静态成员、类外成员函数定义）
function_name       = identifier | class_scope_name ;

# —— 函数（§5.5、§6.4 [1]、§8.2）——
function_decl       = "function" function_name "(" param_list? ")" ( "->" type_spec )? ( block | ";" ) ;
function_proto      = "function" identifier "(" param_list? ")" ( "->" type_spec )? ";" ;
async_function_decl = "async" function_decl ;

# —— 形参（形状）：&/const/array 等类型形状由 type_spec 承担，见 G-3 ——
param_list          = param { "," param } ;
param               = identifier ":" type_spec ;

# —— 迭代（§7.6 [3][4]）——
range_call          = "range" "(" expr "," expr [ "," expr ] ")" ;

# —— 常量表达式（§6.8 [2]）：语法同 expr，常量性由语义检查（见 G-3）——
const_expr          = expr ;

# —— .novai 接口文件（§7.8 [2][3]）：纯声明，语法上就不含函数体、初值与 async ——
# native_iface 见 §7.11；下面给出它的全部成员产生式
native_decl         = native_function_decl | native_class_decl | type_decl | const_decl ;
native_function_decl= "function" identifier "(" param_list? ")" ( "->" type_spec )? ";" ;
native_class_decl   = "class" identifier inheritance? "{" native_member_group* "}" ";"? ;
native_member_group = access_specifier "{" native_member* "}" ;
native_member       = native_field_decl | native_method_decl
                    | native_constructor_decl | native_static_member ;

native_field_decl   = identifier ":" native_field_type ";" ;   # 不得有初值；不得是 const（§7.8 [3]）
native_field_type   = native_value_type | qualified_name ;     # 值类型，或类类型（引用语义的对象）
native_method_decl  = native_method_modifier* "function" native_method_name "(" param_list? ")"
                      ( "->" type_spec )? ";" ;               # 不得有函数体
native_method_modifier = "override" ;                         # **不含 async**（§7.8 [9]）
native_method_name  = identifier ;                            # 不得为 __constructor__（见注 6）

native_constructor_decl = "function" "__constructor__" "(" param_list? ")" ";" ;
                                                              # 无返回类型；不占方法表；不得 async
native_static_member    = "static" ( native_static_field | native_static_method ) ;
native_static_field     = identifier ":" native_static_type ";" ;    # 见注 7
native_static_type      = native_value_type | qualified_name ;      # 别名**照常展开**，展开后须为值类型
native_static_method    = "function" identifier "(" param_list? ")"
                          ( "->" type_spec )? ";" ;           # 无修饰符：不得有体、不得 override / async
native_value_type       = "bool" | "char" | "int" | "float" ;      # §2.6 的值类型
```

> **注**
> 1. `$` **不是**形参的独立语法：它是 `identifier` 的合法字符（§1.2），`$x` 与 `x` 是两个标识符。
>    因此 `param` 里**没有**可选的 `"$"`——若写成 `[ "$" ] identifier` 会在词法层产生二义（§6.4 [5]）。
> 2. `&T` / `const &T` / `array[T | n, m]` 等形状属**类型章节**（`type_spec`），本文件不定义（G-3 只给对照提示）。
> 3. **类外成员函数定义**由 `function_decl` 的 `function_name = class_scope_name` 覆盖；
>    构造函数没有「只声明」形式，**不得**类外定义（§6.5 [1]、§6.14 注 2）。
>    **例外**：`.novai` 接口文件里的 `native_constructor_decl` 是**原生接口专用**的纯声明形式（§7.8 [3]、附录 G-2 注 8），不受此限。
> 4. `native_class_decl` 是 `class_decl` 的**受限版本**：它在**语法**上就不含字段初值、成员函数体与构造函数体，
>    因此 `.novai` 校验不需要「先接受、再后处理拒绝」；在接口文件里写完整 `class_decl` 属**语法**错误（§7.8 [3]）。
> 5. `method_modifier`、`access_specifier`、`inheritance`、`class_decl` 见 §6.14，`type_decl` / `const_decl` 见 §7.11。
>    本附录另定义 **`native_method_modifier`**（只含 `"override"`）与 **`native_value_type`**（只含四个值类型）。
> 6. **构造函数名不得走普通方法产生式**：`native_method_name` 与 `native_static_method` 的名字**不得**为
>    `__constructor__`（它在词法上确实是合法 `identifier`）。带该名字的声明**只能**使用 `native_constructor_decl`，
>    且**不得**带 `override` / `async` / 返回类型。因此下列三种写法在 `.novai` 中都是**语法错误**：
>    `function __constructor__(x: int) -> int;`、`override function __constructor__(x: int);`、
>    `static function __constructor__();`。普通类语法有同样的约束（§6.14 注 2）。
>    **这是「产生式 + 规范性约束」共同确定的边界，不是纯 EBNF 差集**：`native_method_name` 的写法在字形上
>    仍匹配 `__constructor__`。因此对 parser 有两条**规范性**要求：
>    ① 解析到 `function __constructor__` 时**必须优先按 `native_constructor_decl` 候选处理**，
>    仅在它不是「无修饰符、无返回类型、无函数体」的形状时才按本注报错；
>    ② 报错时定位到该成员声明，诊断信息**必须**说明构造函数只能写成 `function __constructor__(...);`
>    （不得只说「意外的 token」）。
> 7. **原生静态字段的类型**：**字面**写 `&T` / `string` / `array` 是**语法错误**（它们不是 `native_static_type`
>    的成员）；写**类类型名**是**格式错误**（语义检查）。**类型别名照常展开**（与 §7.8 [4] 的别名展开一致）：
>    `type Scalar = float;` 后写 `static scale: Scalar;` **合法**（展开为 `float`）；
>    `type Ref = &Widget;` 后写 `static r: Ref;` 为**格式错误**（展开后是引用）。
>    限制的理由是长期存储的语义未闭合——引用只在调用期间有效（§7.8 [7]），GC 对象的长期持有需要 root 登记
>    与写屏障，而本版本没有这些机制。静态字段的存储与读写 ABI 见 §7.8 [3]。
> 8. **「构造函数没有只声明形式」只适用于普通 Nova 类**（§6.14 注 2、§6.5 [1]）：
>    `.novai` 里的 `native_constructor_decl` 正是**原生接口专用**的纯声明形式，不受此限。

### G-3 外部引用的形状提示（**非规范**，仅供对照）

> 下列形状取自 `nova-spec.md` 的**已定条款**，**不是**本文件的定义，**不能**作为实现依据；
> 列出它们只为让读者看清本文件产生式里的 `type_spec`、`expr` 等外部符号大致是什么样。
> 类型 / 表达式 / 语句三章补齐 EBNF 后，**一律以那三章为准**。

```
type_spec  ⊇  &T | const &T | &T const | array[T | n, m] | T（值类型名或类名）   # §2.4、§3.1
expr       ⊇  字面量 | 标识符 | 调用 | 下标 | 成员访问 | 算术/比较/逻辑 | 赋值 | if | match | await | yield   # §1.5、§1.6、§4、§8
statement  ⊇  表达式语句 | let 声明 | return | break | continue | 声明                       # §5
block      =  { statement }（块的值 = 最后一条表达式的值）                                     # §4.1
```

**`const_expr` 的语义约束**（§6.8 [2] 的要求；**语法**与 `expr` 相同，限制在编译期求值阶段检查）：

| 允许 | 不允许 |
|---|---|
| 字面量；`const` 常量名；`static` **常量**成员；对上述量的算术、比较、逻辑运算与显式类型转换 | 函数调用与成员函数调用（含 `uni` 库函数）；对象构造 `类名(...)`；实例字段访问；`await` / `yield`；取引用 `&` |

违反者由 `nvc` 在**编译期求值**阶段诊断为**格式错误**（不是语法错误）。
