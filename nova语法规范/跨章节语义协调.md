## 1. 适用范围与优先级

本文件只处理已经出现的跨章节冲突，不重新设计没有冲突的语法。优先级如下：

1. `nova-spec.md` 中已有的 `✔` 条款继续有效；本文只细化其中明确留白的边界。
2. 第二章定义词法和基础类型，第三章定义表达式、赋值、控制流和函数调用，第四章定义类、模块、异步和 ABI。
3. 同一条规则在多个章节出现时，以本文的统一条款为准；章节文件只保留主题说明，不再各自发明另一套行为。
4. 本文没有把未定的标准库 API、GC 算法、调度器策略和目标平台宽度伪装成定论。

## 2. 冲突统一表

| 编号 | 冲突主题 | 统一结论 | 主要落点 |
|---|---|---|---|
| S-01 | 局部变量零值 / 确定性初始化 | 局部变量无初始化器时处于“未初始化”状态；读取前必须证明已写入。字段仍按第四章规则初始化。 | §2、§3.1 |
| S-02 | `int` 溢出回绕 / trap | 32 位有符号 `int` 的算术溢出统一 trap；不采用回绕。 | §3.2 |
| S-03 | `char`、`bool` 和数值转换 | `char` 不直接参加算术，须显式转 `int`；`bool` 只进入逻辑运算组；非法窄化转换 trap。 | §3.3 |
| S-04 | 函数重载 | 普通函数和成员函数都允许重载；参数类型列表区分；按精确匹配和固定提升链选唯一最佳候选。 | §3.4 |
| S-05 | `main` 形态和退出码 | `main()` 无参数、返回 `int`；允许 `async main()`；命令行参数由标准库提供；进程边界取返回值的模 256 结果。 | §3.5 |
| S-06 | `for` 变量别名 / 副本 | 循环变量是只读副本；类、数组、字符串元素复制句柄，不复制对象内容。 | §3.6 |
| S-07 | 数组切片和多维下标 | 数组保留定长、多维、行主序；支持完整维度下标；不引入数组切片类型或隐式切片复制。 | §3.7 |
| S-08 | `string` 表示 | `string` 是不透明句柄和 UTF-8 字节序列；长度和索引按字节；切片是只读视图，不复制缓冲区。 | §3.8 |
| S-09 | `const &T` / `&T const` | 两种写法都合法但含义不同：前者限制被引用对象，后者是调用期间的只读参数视图。 | §3.9 |
| S-10 | 对象拷贝 / 句柄复制 | 赋值、传参和返回只复制句柄；不隐式深拷贝或生成拷贝构造。需要独立对象必须显式构造或调用复制 API。 | §3.10 |
| S-11 | 类布局和 ABI | 采用第四章的单继承、单 `vptr`、声明顺序字段和方法表规则；目标平台只决定 `vptr` 的宽度和对齐。 | §3.11 |
| S-12 | 浮点除零 / 整数除零 | 整数除零 trap；浮点除零遵循 IEEE 754，产生无穷或 NaN。 | §3.12 |
| S-13 | `range` 零步长 | 语义统一为 trap；若编译期能证明步长为零，可以提前报同一错误。 | §3.13 |
| S-14 | `import`、`async` 和优先级 | 第二章只保留关键字；完整语法由第四章提供；表达式优先级只维护一张表。 | §3.14 |
| S-15 | `if`/`match` 分支类型统一 | 值语境的各分支必须**完全同型**，不自动提升；需要混型写显式转换。 | §3.15 |
| S-16 | 返回类型省略 | 省略 `-> T` 时从所有带值 `return` 推导（同型则取该型，无带值返回则 `void`），不再等同 `-> void`。 | §3.16 |
| S-17 | 函数值 | 函数名**不是一等值**：不可作实参、不可绑定、不可存储；无 lambda / 闭包。 | §3.17 |
| S-18 | 包级可变变量 | 模块顶层只允许 `const`（编译期常量），**不存在**包级可变 `let`。 | §3.18 |
| S-19 | 类类型转换 | 派生类 → 基类**隐式向上转换**合法；向下转换与类↔值转换不提供。 | §3.19 |
| S-20 | 类声明的值 | 类声明是**声明语句**，无值、不可出现在表达式位置。 | §3.20 |
| S-21 | `range` 身份 | `range` 是 `for` 迭代位的**语言内建构造**，非一等值、无返回对象；`uni` 表中的条目按此理解。 | §3.21 |
| S-22 | 优先级：关系与相等 | 关系（`< > <= >=`）与相等（`== <>`）**分两级**（关系高于相等），对合法程序与合并表无差，取传统两级表。 | §3.22 |
| S-23 | `await` 得 void 任务 | `await` 结果类型为 `void` 时不可绑定、不可作操作数，只能作表达式语句丢弃。 | §3.23 |
| S-24 | `for` 可迭代对象 | `array`、`string`、切片均可作为**同步序列**直接迭代（生成器流为异步序列）。 | §3.24 |
| S-25 | `break` 跳出 `match` | `break` / `continue` **只作用于循环**，不跳出 `match`（分支执行完自然结束）。 | §3.25 |
| S-26 | 继承中的重载查找 | 成员函数查找采**遮蔽制**：自派生向基类逐层找，命中的第一个同名成员集为候选集，更基类的同名重载集被遮蔽（经 `super.` 调用）；不收集全链候选。 | §3.26 |
| S-27 | `::` 与优先级表 | `qualified_name` 词法归并为原子项，"优先级最高"由构造保证，不另列运算符行。 | §3.27 |
| S-28 | `type()` 类转换 | 类类型**仅隐式向上转换**，**不提供显式 `type()`**（与构造调用同形、文法无法消歧，且转换恒安全无需显式形式）；`T(expr)` 封闭为值类型转换。 | §3.28 |
| S-29 | `return` 加宽 | `return` 表达式的类型可沿提升链**加宽**到返回类型（`int`→`float`），与赋值/实参匹配一致；收窄须显式转换。 | §3.29 |
| S-30 | `super` 构造调用 | 显式构造函数必须写 `super.__constructor__(...)`、**无例外**（spec §6 已定优先）；唯一豁免是**隐式无参构造函数**自动调用基类无参构造（生成代码，非源码省略）。 | §3.30 |

## 3. 统一语义条款

### 3.1 局部变量与字段初始化（S-01）

```nova
let x: int;       # 合法，但 x 目前未初始化
input(x);         # 输出参数写入 x，此后 x 已初始化
println(x);       # 合法
```

- `let x: T;` 合法并创建未初始化槽位；`let x;` 仍非法。
- 每条可能到达读取点的路径都必须已经写入该槽位。编译器执行路径敏感的确定性初始化分析。
- `input(x)`、`format` 等被标准库声明为输出参数的调用算作写入；普通函数调用不能被默认当成写入。
- 形参在函数进入时已初始化。引用参数还必须通过生命周期检查。
- 类字段沿用第四章：值类型字段无初值时取零值；类类型字段必须有声明初值，不能用空引用代替。
- 包级初始化继续遵循主规范的编译期求值规则；本条只改变局部变量，不把运行时初始化偷偷引入链接阶段。

这样既能表达 `hanoi.nova` 的 `input(n)`，也能表达 `point.nova` 的格式化输出，同时不会让读取未写入的栈槽位变成实现相关行为。

### 3.2 `int` 溢出和整数错误（S-02）

- `int` 是 32 位有符号二补数，合法范围为 `-2^31 .. 2^31-1`。
- 加、减、乘、整数除法的商和显式窄化只要超出范围，统一触发 `NOVA-R-INT-OVERFLOW` trap。
- `-2^31 / -1` 也触发同一 trap；整数除法本身向零截断，余数与被除数同号。
- 不采用第二章工作稿中的静默回绕。需要回绕时必须由标准库提供显式函数。

### 3.3 `char`、`bool` 和转换（S-03）

- `char` 是一个字节的字符值。`char` 不能直接作为 `+`、`-`、`*`、`/`、`%` 的操作数；算术前必须写 `int(c)`。
- **算术与比较中 `int → float` 自动提升合法**（`int + float` → `float`，第三章 3.3.4）；被禁止的仅是 `char` 的自动提升。此规则与 S-15（`if`/`match` 分支类型完全同型）是两条独立规则：运算数提升 ≠ 分支类型统一。
- 非算术的赋值、实参匹配和重载排序仍使用单向提升链 `char → int → float`。
- **`return` 表达式也允许沿提升链加宽到返回类型**（`int` 可返回给 `float`，S-29；与赋值/实参匹配同性质）。第二章 2.8.5 原已允许，第三章 3.4.1 原「必须同型值」已按本条订正。
- `bool` 只进入 `and`、`or`、`xor`、`not` 逻辑运算组；不参加算术、排序或数值转换。`bool` 的同型 `==` / `<>` 比较仍然可以使用。
- `float → int` 向零截断；NaN、无穷和越界 trap。
- `int → char` 只接受 `0..127`；超出范围 trap，不回绕。
- `float → char` 先向零截断，再按 `0..127` 检查。
- `int → bool` 不提供内建转换；需要判断非零时写 `x <> 0`。

### 3.4 函数和成员函数重载（S-04）

- 普通函数和成员函数都可以重载。
- 函数签名键为“限定名 + 参数类型列表”；返回类型不参与区分。
- 候选按以下顺序排序：
  1. 参数数量和名字匹配；
  2. 所有参数完全精确匹配；
  3. 必要时使用 `char → int → float` 的单向提升，提升次数更少者优先；
  4. 仍有多个同等候选时，报告 `NOVA-E-OVERLOAD`，不得由运行时猜测。
- `override` 必须命中基类同签名成员；重载不会自动变成重写。
- 不支持按返回类型重载、运行时重载、函数值、lambda 或闭包。
- **成员函数的继承查找采遮蔽制（S-26）**：派生类声明同名成员集即遮蔽基类同名重载集，跨层收集不发生；被遮蔽版本经 `super.名字(...)` 调用。详见 §3.26。

这统一了第三章的提升排序和第四章的成员重载；第二章“包作用域唯一函数名”只作为早期草案，不再适用。

### 3.5 程序入口、异步入口和退出码（S-05）

合法入口只有以下两种形态：

```nova
function main() -> int { ... }
async function main() -> int { ... }
```

- `main` 不接受形参；不得使用 `main(args: ...)`。
- 异步入口由运行时启动并等待其任务完成，再取得返回值。
- 命令行参数由 `uni` 标准库接口提供；接口名称和容器类型属于标准库章节，不改变 `main` 签名。
- Nova 层的返回值是完整 `int`；进程启动器在系统边界使用 `result mod 256` 作为可观察退出码。
- 入口缺失、重复或返回类型不是 `int` 都是编译期错误。

### 3.6 `for` 循环变量（S-06）

```nova
for x in range(0, n) {
    # x 是只读副本
}
```

- 循环变量在每轮迭代开始时取得元素的值，不是隐式引用，也不是可写左值。
- 值类型复制值；类、数组和字符串复制句柄，仍指向同一对象或缓冲区。
- 需要修改数组元素时使用 `a[i]` 或显式引用；不能给循环变量赋值来修改集合。
- 循环变量的生命周期只覆盖循环体，不能返回或保存为逃逸引用。

### 3.7 数组维度、下标和切片（S-07）

- 数组是定长类型，维度和每一维长度属于类型；存储采用行主序连续布局。
- 多维数组使用**逗号全维下标** `a[i, j]`，一次消费全部维度（2026-09-24 修订：原"`a[i][j]` 链式、部分下标不产生视图"两条互斥——链式访问必然要求 `a[i]` 产生行视图。统一采逗号下标，与第二章 2.6.4.2、第三章 3.4.3 一致）。
- 一维数组的 `a[i]` 返回元素左值；越界立即 trap。
- `length()` 返回所有维度元素总数。
- 数组不支持 `[n:m]` 切片语法，不产生隐式切片类型；需要独立数组时调用显式复制函数。
- `&array` 是接受定长数组句柄的顶层参数形状；`const &array` 只读，不能通过下标写入。

### 3.8 `string` 句柄、编码和切片（S-08）

- `string` 是不透明句柄，逻辑内容为 UTF-8 字节序列；句柄的物理宽度由目标 ABI 固定。
- `length()` 返回字节数；`s[i]` 的索引单位也是字节，返回只读字符单元引用。
- `s[n:m]` 是左闭右开只读视图，返回 `&string`，不复制底层缓冲区；视图不能逃出原字符串的生命周期。
- `==` / `<>` 按 UTF-8 字节内容比较；不支持字符串排序运算。
- 赋值、传参和返回只复制句柄。`format` 等标准库输出操作可以初始化一个未初始化的 `string` 槽位，但不改变已存在字符串的不可变内容。
- 原生包只能通过不透明句柄接口访问字符串，不依赖内部指针字段。

### 3.9 引用 `const` 位置（S-09）

| 写法 | 统一语义 |
|---|---|
| `&T` | 可写引用，只能绑定稳定且可写的左值；引用本身不重绑定 |
| `const &T` | 被引用对象只读；只能绑定稳定左值，不能通过该引用写入 |
| `&T const` | 调用期间的只读参数视图；可绑定稳定左值、字面量或临时值，临时对象不得逃出调用 |

- 三种形状不产生不同的重载签名；它们只影响绑定检查、写权限和生命周期检查。
- 引用返回值必须指向仍存活的对象；禁止返回局部变量、临时对象或已失效字符串视图。

### 3.10 句柄复制和显式对象复制（S-10）

- 复制 `class`、`array`、`string` 变量时复制句柄，不复制对象或底层字节。
- 这不等于“隐式拷贝构造”：Nova 不自动生成独立对象副本，也不自动调用用户构造函数。
- 需要独立副本时，必须写显式构造调用或标准库复制函数；复制函数的具体名称属于标准库章节。
- 简单值类型仍按值复制；引用类型的生命周期和可写性检查先于句柄复制。

### 3.11 类布局和 ABI（S-11）

- 采用单继承；完整对象偏移 0 放一个 `vptr`，其后按基类字段、派生类新增字段的声明顺序排布。
- 访问组顺序不影响布局；静态字段和成员函数不占对象存储。
- 方法表按“基类先、声明顺序后”排列；`override` 复用基类槽位，新成员追加槽位。
- `vptr` 的宽度和对齐由目标平台 ABI 决定，但同一目标三元组必须固定；对象布局元数据由 `nvc` 写入、由 `nvld` 校验。
- `array` 和 `string` 使用句柄接口，不把其内部存储强行当作普通类字段布局。

### 3.12 浮点和整数除零（S-12）

- 整数除零、整数商溢出和数组/字符串越界统一 trap。
- `float` 使用 IEEE 754：有限非零值除以零产生带符号无穷，零除以零产生 NaN；不触发整数错误码。
- NaN 的比较规则沿第三章：`==` 为 `false`，`<>` 为 `true`，排序比较均为 `false`。

### 3.13 `range` 步长（S-13）

- `range(stop)`、`range(start, stop)` 和 `range(start, stop, step)` 的终点均不包含。
- 步长为负数时按递减方向迭代；步长为零的语义是 trap。
- 若 `nvc` 在常量求值阶段已经证明步长为零，可以直接报告编译期错误，但错误码和运行时 trap 相同。

### 3.14 关键字、模块和优先级（S-14）

- `async`、`await`、`yield` 在第二章中只是保留关键字；语法和执行语义由第四章定义。
- `import` 作为模块语法的关键字由第四章定义，必须同步加入词法关键字表；不能在第二章另定义一套导入规则。
- `::` 名称解析、模块可见性、原生接口和 `nvp` 构建规则只由第四章章节负责。
- 运算符优先级只维护一张表：调用/下标/成员访问最高，其次是一元运算、乘除模、加减、比较、`and`、`xor`、`or`，最后是赋值和多目标赋值。
- 章节中的 EBNF 只能引用这张优先级表；重复表述若不一致，以主规范回填后的版本为准。

### 3.15 `if` / `match` 分支类型（S-15）

- 值语境（作表达式使用）的 `if` / `match`：各可达分支的块值类型必须**完全同型**，不引入公共提升类型（第二章 2.7.9、第三章 3.3.3 一致）。
- 需要混型时由程序员写显式转换：`if c { float(1) } else { 2.0 }`。
- 理由：隐式规则越少，重载决议（S-04 的提升排序）与分支统一越不会互相制造歧义；与 S-03「算术不自动提升」同一哲学。

### 3.16 返回类型省略（S-16）

- 函数省略 `-> T` 时，**从函数体内所有带值 `return` 推导**：全部同型则该型；没有任何带值返回则 `void`（第三章 3.4.1）。
- 原第二章「省略 ≡ `-> void`」作废——它使 `point.nova` 的 `__constructor__`（无返回类型、无带值 return，推导结果恰为 `void`，两版兼容）之外的带值返回写法（如 `function log(m: string) { ... }` 想推 `void` 以外的东西）失去表达力。
- 推导仍限局部（单函数内），不引入全局推断引擎。

### 3.17 函数不是一等值（S-17）

- `function` 名只能出现在声明与调用位置；不可作实参、不可绑定 `let`、不可存入字段或数组；无 lambda、无闭包（第三章 3.4.2）。
- 原第二章 D-45「函数可作实参」收回：函数指针的 ABI（fat pointer 问题）三章均无定义，不开这个口子。
- 高阶需求（如按不同键排序）将来若要做，随函数指针 ABI 一起定，属增量语法之外的新章节议题。

### 3.18 包级无可变变量（S-18）

- 模块顶层只允许：`import`、`class`、`function`、`type`、`const`（初值为编译期常量表达式）、以上加 `private`（第四章 7.1 [3]）。
- **不存在**包级可变 `let`；原第二章作用域/存储期表中的「包作用域 `let`」已删（第二章 2.5.1、2.5.4、2.9.3）。
- 理由：顶层无可变状态 ⇒ 无模块初始化函数 ⇒ 无静态初始化顺序问题 ⇒ 循环 `import` 安全——第四章整套设计以此为前提。

### 3.19 类类型转换（S-19）

- 派生类 → 基类：**隐式向上转换**合法（无需显式写法），也可按 `type()` 形式书写（第四章 6.7 [8]、6.11 [8]；第二章 2.6.1、2.6.7.2 已同步）。
- 基类 → 派生类：不提供（无 RTTI）；类 ↔ 值类型：不提供。
- 原第二章「类类型之间无转换」表述作废。

### 3.20 类声明无值（S-20）

- 类声明（与函数声明、`type` 别名并列）是**声明语句**，无值、不可出现在表达式位置（第二章 2.7.8 语句封闭清单）。
- 第四章 6.1 [5] 原「类声明的值是 `none`」已按本条改写——那是对「一切皆表达式」的过度延伸，且与语句封闭清单冲突。

### 3.21 `range` 是内建构造（S-21）

- `range(...)` 只在 `for ... in range(...)` 的迭代位出现，语法特判、编译为计数循环；**不返回值对象**，不可 `let r = range(5)`（第二章 2.8.4 / D-22）。
- 第四章 7.6 [3] 把 `range` 列在 `uni` 语言级入口表中——该表读作「`uni` 名义下的语言级入口清单」，`range` 条目按本条理解，不是普通库函数；表注已补。
- 理由：无泛型、无迭代器类型，`range` 若是普通函数则无返回类型可写。

### 3.22 优先级表：关系与相等分两级（S-22）

- 统一优先级表（第二章 2.4.8、第三章 3.4.6 已同步为同一张 10 级表）：

```
1 后缀 ( ) [ ] .      2 一元 - + not      3 * / %        4 + -
5 < > <= >=           6 == <>             7 and          8 xor
9 or                  10 = 与多目标赋值
```

- 第三章原「比较全并一级」与第二章「两级」的差别，经分析**对合法程序解析结果无差**（合并后 `a == b < c` 左结合得 `(a==b) < c`，而 bool 不可排序，两版都类型错误），故取 C/C++/Rust 传统的两级表，避免将来引入 bool 排序类特性时堵路。
- 本条取代 S-14 中「只维护一张表」的悬置：表的内容即上框。

### 3.23 `await` 得 void 任务（S-23）

- `await` 目标任务结果类型为 `void` 时，表达式类型为 `void`、值为 `none`——按全局 void 纪律（不可绑定、不可作实参/操作数），**只能**作表达式语句丢弃：`await f();` 合法，`let x = await f();` 移植期错误（第四章 8.3 [4]④ 已按此改写）。
- 理由：为异步开「可绑定 void」的例外会破坏 S 系列里 D-26 一脉的 void 纪律。

### 3.24 `for` 可迭代对象（S-24）

- 同步序列：`range(...)` 调用、`array`（表达式）、`string`（表达式）、字符串切片——均可 `for x in ...` 直接迭代（第二章 2.8.4、第三章 3.3.6 一致）。
- 异步序列：生成器流 `Stream⟨f⟩`（第四章 8.4），`for` 迭代它是切换点、须在异步函数体内。
- 第四章 8.11 第 4 项、附录 B-2 第 3 项按本条**销号**。

### 3.25 `break` 不跳出 `match`（S-25）

- `break` / `continue` 只作用于最内层**循环**；`match` 分支执行完自然结束，不存在「跳出 match」的可观察效果（第二章 2.8.4、第三章 3.3.6 已统一）。
- 第三章原文「`break` 跳出最近的循环或 `match`」已按本条改写。
- 理由：保持「跳转语句语义单一」；`match` 分支内的循环由该循环自身管理。

### 3.26 继承中的重载查找（S-26）

- 成员函数调用的名字查找采**遮蔽制**（C++ 式 name hiding），与第四章 6.4 [3]、6.6 [8] 一致：
  - 在对象的静态类型上，自派生类向基类**逐层**查找声明了该名字的类；
  - **命中的第一个类**上声明的全部同名成员函数构成候选集；
  - 更基类的同名重载集被**遮蔽**，不参与本次重载决议；
  - 需要调用被遮蔽的基类版本，必须显式写 `super.名字(...)`（第四章 6.6 [8]）。
- **推翻**第三章 3.4.2 原步骤 3「沿单继承链向基类查找未被同签名成员覆盖的候选」——该表述是「收集全链候选」的 Java/C# 式模型，与第四章的遮蔽制直接矛盾（同一调用 `f(1)` 在两章下结论相反）。第三章已按本条改写。
- 理由：第四章整套对象模型（名字查找顺序 §6.4[3]、遮蔽示例 §6.6[8]、`super.` 逃逸）都以遮蔽制为前提，改第四章代价远大于改第三章一处；遮蔽制也让「裸名 = 单一来源集」更可控，符合本语言「歧义必须显式消解」的一贯取向。
- 与 `override` 的关系不变：同签名仍是重写（占同一方法表槽位），遮蔽只发生在**同名不同签名**时。

### 3.27 `::` 与优先级表（S-27）

- `::` 不进入第二章 2.4.8 / 第三章 3.4.6 的运算符优先级表：`qualified_name`（`a::b::c`）在词法/文法层归并为**单个原子项**（第二章 2.7.2 `primary-expression`），其「优先级最高」（第四章 7.4 [1]）由构造保证，无需列为独立运算符行。
- 第四章 7.4 [1] 引用「§1.6 优先级最高」时，读作「`::` 结合先于任何运算符、且左操作数只能是名字」——与原子项归并等价，无冲突。
- 第二章 2.4.8 已加注说明本条。

### 3.28 类类型转换仅隐式（S-28）

- 派生类 → 基类：**隐式**转换，恒安全；**不提供**显式 `type()` 形式。基类 → 派生类、类 ↔ 值类型均不提供（第四章 §6.11 [8]）。
- 理由：类名调用即构造调用（第四章 §6.5 [3]）。若允许 `Base(derived_expr)` 作转换写法，则与「构造一个接受派生类型参数的 `Base`」在文法上同形、无法消歧；而向上转换无失败通道、恒安全，本就不需要显式形式。
- `T(expr)` 中的 `T` 封闭为 `char` / `int` / `float`（第二章 §2.6.7.2 已加注）。
- 第四章 §6.11 [8] 已按本条删除原「也可写 `type()`」。

### 3.29 `return` 加宽（S-29）

- `return e` 中 `e` 的类型与返回类型相同，或沿 `char → int → float` 提升链**加宽**到返回类型；反向（收窄）必须显式转换。
- 依据：`return` 本质是「向调用方交付结果」，与赋值、实参匹配同性质，理应享受同向提升；第二章 2.8.5 原已允许，第三章 3.4.1 原「必须同型值」是更早草案的残留，已订正。

### 3.30 `super` 构造调用统一（S-30）

- **显式**构造函数必须显式写出 `super.__constructor__(实参);` 且必须是构造函数体第一条语句——**无例外**（`nova-spec.md` §6 的课堂已定结论优先于章节提案）。
- **唯一豁免：隐式生成的无参构造函数**。类未声明任何构造函数时，其隐式无参构造函数若有基类，自动在构造顺序第 ② 步调用基类的无参构造函数（`nvc` 生成代码，不要求也不允许源码书写）；基类没有可用的无参构造函数时，该类必须显式声明构造函数，否则为格式错误。
- **裁决过程**：第四章 §6.5 [8] 曾允许「基类有无参构造时，显式构造也可省略 `super`」——这是第四章分支的边界扩展提案，与 spec §6 正面矛盾且未经课堂确认。按仓库权威顺序（spec 为唯一权威规范、课堂已定项不得单方面推翻），**否决该例外**；同时为保持规则自洽（隐式构造函数不可能手写 `super`），把隐式构造的自动调用显式化为唯一豁免——它不是源码层省略，不构成已定结论的例外。
- 已回改：第四章 §6.5 [4][6][7][8]、`nova-spec.md` §6、设计取舍报告 A-8（原候选 ③ 的例外作废）。

## 4. 工具链实现影响

### `nvc`

- 符号状态至少区分“未初始化、已初始化、不可继续”；字段初始化和局部确定性初始化使用两套规则。
- 类型检查同时记录类型、值类别、写权限和生命周期；`const &T` 与 `&T const` 不进入不同重载键。
- 重载候选排序、显式转换、整数溢出和边界检查在常量求值和运行时代码生成中复用同一套规则。
- 数组类型记录完整维度；多维下标必须消费全部维度；数组切片直接报格式错误。
- `async main` 降级为启动器可等待的根任务；普通 `main` 直接调用同一退出码封装。

### `nvld`

- 函数符号至少包含限定名和参数类型列表，返回类型不进入符号键。
- 类元数据包含字段偏移、对齐、`vptr`/方法表布局和 ABI 版本；链接器拒绝不兼容的类元数据。
- 句柄、引用和退出码只按目标平台调用约定连接；链接器不重新执行表达式重载决议。

### 编辑器连接器

- 悬停分别显示值、句柄、只读引用和可写引用；对未初始化读取显示 `NOVA-E-USE-BEFORE-INIT`。
- 重载歧义、非法转换、数组部分下标和切片错误在编辑器中使用稳定错误码定位到表达式。
- `async`、`import`、多维下标和多目标赋值使用同一份语法树，不为章节工作稿提供平行语法。
