## 1. 适用范围与优先级

本文件只处理已经出现的跨章节冲突，不重新设计没有冲突的语法。优先级如下：

1. `nova-spec.md` 中已有的 `✔` 条款继续有效；本文只细化其中明确留白的边界。
2. 第二章定义词法和基础类型，第三章定义表达式、赋值、控制流和函数调用，第四章定义类、模块、异步和 ABI。
3. 同一条规则在多个章节出现时，以本文的统一条款为准；章节文件只保留主题说明，不再各自发明另一套行为。
4. 本文没有把未定的标准库 API、GC 算法、调度器策略和目标平台宽度伪装成定论。

## 3. 统一语义条款

### 3.1 局部变量与字段初始化（S-01）

```nova
let x: int;       # 合法，但 x 目前未初始化
input(x);         # 输出参数写入 x，此后 x 已初始化
println(x);       # 合法
```

- `let x: T;` 合法并创建未初始化槽位；`let x;` 仍非法。
- 每条可能到达读取点的路径都必须已经写入该槽位。编译器执行路径敏感的确定性初始化分析。
- `input(x)`、`format` 等被标准库声明为输出参数的调用算作写入；普通函数调用不能被默认当成写入。
- 形参在函数进入时已初始化。引用参数还必须通过生命周期检查。
- 类字段沿用第四章：值类型字段无初值时取零值；类类型字段必须有声明初值，不能用空引用代替。
- 包级初始化继续遵循主规范的编译期求值规则；本条只改变局部变量，不把运行时初始化偷偷引入链接阶段。

这样既能表达 `hanoi.nova` 的 `input(n)`，也能表达 `point.nova` 的格式化输出，同时不会让读取未写入的栈槽位变成实现相关行为。

### 3.2 `int` 溢出和整数错误（S-02）

- `int` 是 32 位有符号二补数，合法范围为 `-2^31 .. 2^31-1`。
- 加、减、乘、整数除法的商和显式窄化只要超出范围，统一触发 `NOVA-R-INT-OVERFLOW` trap。
- `-2^31 / -1` 也触发同一 trap；整数除法本身向零截断，余数与被除数同号。
- 不采用第二章工作稿中的静默回绕。需要回绕时必须由标准库提供显式函数。

### 3.3 `char`、`bool` 和转换（S-03）

- `char` 是一个字节的字符值。`char` 不能直接作为 `+`、`-`、`*`、`/`、`%` 的操作数；算术前必须写 `int(c)`。
- 非算术的赋值、实参匹配和重载排序仍使用单向提升链 `char → int → float`。
- `bool` 只进入 `and`、`or`、`xor`、`not` 逻辑运算组；不参加算术、排序或数值转换。`bool` 的同型 `==` / `<>` 比较仍然可以使用。
- `float → int` 向零截断；NaN、无穷和越界 trap。
- `int → char` 只接受 `0..127`；超出范围 trap，不回绕。
- `float → char` 先向零截断，再按 `0..127` 检查。
- `int → bool` 不提供内建转换；需要判断非零时写 `x <> 0`。

### 3.4 函数和成员函数重载（S-04）

- 普通函数和成员函数都可以重载。
- 函数签名键为“限定名 + 参数类型列表”；返回类型不参与区分。
- 候选按以下顺序排序：
  1. 参数数量和名字匹配；
  2. 所有参数完全精确匹配；
  3. 必要时使用 `char → int → float` 的单向提升，提升次数更少者优先；
  4. 仍有多个同等候选时，报告 `NOVA-E-OVERLOAD`，不得由运行时猜测。
- `override` 必须命中基类同签名成员；重载不会自动变成重写。
- 不支持按返回类型重载、运行时重载、函数值、lambda 或闭包。

这统一了第三章的提升排序和第四章的成员重载；第二章“包作用域唯一函数名”只作为早期草案，不再适用。

### 3.5 程序入口、异步入口和退出码（S-05）

合法入口只有以下两种形态：

```nova
function main() -> int { ... }
async function main() -> int { ... }
```

- `main` 不接受形参；不得使用 `main(args: ...)`。
- 异步入口由运行时启动并等待其任务完成，再取得返回值。
- 命令行参数由 `uni` 标准库接口提供；接口名称和容器类型属于标准库章节，不改变 `main` 签名。
- Nova 层的返回值是完整 `int`；进程启动器在系统边界使用 `result mod 256` 作为可观察退出码。
- 入口缺失、重复或返回类型不是 `int` 都是编译期错误。

### 3.6 `for` 循环变量（S-06）

```nova
for x in range(0, n) {
    # x 是只读副本
}
```

- 循环变量在每轮迭代开始时取得元素的值，不是隐式引用，也不是可写左值。
- 值类型复制值；类、数组和字符串复制句柄，仍指向同一对象或缓冲区。
- 需要修改数组元素时使用 `a[i]` 或显式引用；不能给循环变量赋值来修改集合。
- 循环变量的生命周期只覆盖循环体，不能返回或保存为逃逸引用。

### 3.7 数组维度、下标和切片（S-07）

- 数组是定长类型，维度和每一维长度属于类型；存储采用行主序连续布局。
- 多维数组使用完整维度下标，例如 `a[i][j]`；部分下标不能隐式产生新的数组视图。
- 一维数组的 `a[i]` 返回元素左值；越界立即 trap。
- `length()` 返回所有维度元素总数。
- 数组不支持 `[n:m]` 切片语法，不产生隐式切片类型；需要独立数组时调用显式复制函数。
- `&array` 是接受定长数组句柄的顶层参数形状；`const &array` 只读，不能通过下标写入。

### 3.8 `string` 句柄、编码和切片（S-08）

- `string` 是不透明句柄，逻辑内容为 UTF-8 字节序列；句柄的物理宽度由目标 ABI 固定。
- `length()` 返回字节数；`s[i]` 的索引单位也是字节，返回只读字符单元引用。
- `s[n:m]` 是左闭右开只读视图，返回 `&string`，不复制底层缓冲区；视图不能逃出原字符串的生命周期。
- `==` / `<>` 按 UTF-8 字节内容比较；不支持字符串排序运算。
- 赋值、传参和返回只复制句柄。`format` 等标准库输出操作可以初始化一个未初始化的 `string` 槽位，但不改变已存在字符串的不可变内容。
- 原生包只能通过不透明句柄接口访问字符串，不依赖内部指针字段。

### 3.9 引用 `const` 位置（S-09）

| 写法 | 统一语义 |
|---|---|
| `&T` | 可写引用，只能绑定稳定且可写的左值；引用本身不重绑定 |
| `const &T` | 被引用对象只读；只能绑定稳定左值，不能通过该引用写入 |
| `&T const` | 调用期间的只读参数视图；可绑定稳定左值、字面量或临时值，临时对象不得逃出调用 |

- 三种形状不产生不同的重载签名；它们只影响绑定检查、写权限和生命周期检查。
- 引用返回值必须指向仍存活的对象；禁止返回局部变量、临时对象或已失效字符串视图。

### 3.10 句柄复制和显式对象复制（S-10）

- 复制 `class`、`array`、`string` 变量时复制句柄，不复制对象或底层字节。
- 这不等于“隐式拷贝构造”：Nova 不自动生成独立对象副本，也不自动调用用户构造函数。
- 需要独立副本时，必须写显式构造调用或标准库复制函数；复制函数的具体名称属于标准库章节。
- 简单值类型仍按值复制；引用类型的生命周期和可写性检查先于句柄复制。

### 3.11 类布局和 ABI（S-11）

- 采用单继承；完整对象偏移 0 放一个 `vptr`，其后按基类字段、派生类新增字段的声明顺序排布。
- 访问组顺序不影响布局；静态字段和成员函数不占对象存储。
- 方法表按“基类先、声明顺序后”排列；`override` 复用基类槽位，新成员追加槽位。
- `vptr` 的宽度和对齐由目标平台 ABI 决定，但同一目标三元组必须固定；对象布局元数据由 `nvc` 写入、由 `nvld` 校验。
- `array` 和 `string` 使用句柄接口，不把其内部存储强行当作普通类字段布局。

### 3.12 浮点和整数除零（S-12）

- 整数除零、整数商溢出和数组/字符串越界统一 trap。
- `float` 使用 IEEE 754：有限非零值除以零产生带符号无穷，零除以零产生 NaN；不触发整数错误码。
- NaN 的比较规则沿第三章：`==` 为 `false`，`<>` 为 `true`，排序比较均为 `false`。

### 3.13 `range` 步长（S-13）

- `range(stop)`、`range(start, stop)` 和 `range(start, stop, step)` 的终点均不包含。
- 步长为负数时按递减方向迭代；步长为零的语义是 trap。
- 若 `nvc` 在常量求值阶段已经证明步长为零，可以直接报告编译期错误，但错误码和运行时 trap 相同。

### 3.14 关键字、模块和优先级（S-14）

- `async`、`await`、`yield` 在第二章中只是保留关键字；语法和执行语义由第四章定义。
- `import` 作为模块语法的关键字由第四章定义，必须同步加入词法关键字表；不能在第二章另定义一套导入规则。
- `::` 名称解析、模块可见性、原生接口和 `nvp` 构建规则只由第四章章节负责。
- 运算符优先级只维护一张表：调用/下标/成员访问最高，其次是一元运算、乘除模、加减、比较、`and`、`xor`、`or`，最后是赋值和多目标赋值。
- 章节中的 EBNF 只能引用这张优先级表；重复表述若不一致，以主规范回填后的版本为准。

## 4. 工具链实现影响

### `nvc`

- 符号状态至少区分“未初始化、已初始化、不可继续”；字段初始化和局部确定性初始化使用两套规则。
- 类型检查同时记录类型、值类别、写权限和生命周期；`const &T` 与 `&T const` 不进入不同重载键。
- 重载候选排序、显式转换、整数溢出和边界检查在常量求值和运行时代码生成中复用同一套规则。
- 数组类型记录完整维度；多维下标必须消费全部维度；数组切片直接报格式错误。
- `async main` 降级为启动器可等待的根任务；普通 `main` 直接调用同一退出码封装。

### `nvld`

- 函数符号至少包含限定名和参数类型列表，返回类型不进入符号键。
- 类元数据包含字段偏移、对齐、`vptr`/方法表布局和 ABI 版本；链接器拒绝不兼容的类元数据。
- 句柄、引用和退出码只按目标平台调用约定连接；链接器不重新执行表达式重载决议。

### 编辑器连接器

- 悬停分别显示值、句柄、只读引用和可写引用；对未初始化读取显示 `NOVA-E-USE-BEFORE-INIT`。
- 重载歧义、非法转换、数组部分下标和切片错误在编辑器中使用稳定错误码定位到表达式。
- `async`、`import`、多维下标和多目标赋值使用同一份语法树，不为章节工作稿提供平行语法。
