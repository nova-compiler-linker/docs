# 3.3 表达式、转换与控制流

## 结论

### 3.3.1 块和表达式语句

- 声明不是值表达式；函数调用是表达式，函数名不是值。
- 块的值是最后一个表达式的值。
- 空块、以声明结尾的块和循环块的类型都是 `void`，值为 `none`。
- `return`、`break`、`continue` 不产生普通值。
- 任何表达式都可以写成 `expr;`；结果丢弃，副作用保留。

```nova
println("start");     # 普通值被丢弃
{};                    # void/none 也合法
a = a + 1;             # 写入副作用保留
```

`void` 没有运行时存储；`none` 只在类型检查和控制流分析中作为 `void` 的值名出现，不能绑定到变量、作为普通参数或参与运算。

### 3.3.2 求值顺序

普通表达式、函数参数、成员访问和下标访问统一从左到右求值。逻辑运算单独规定：

- `and`：左侧为 `false` 时跳过右侧；
- `or`：左侧为 `true` 时跳过右侧；
- `xor`：两侧都求值，不短路。

### 3.3.3 `if` 和 `match`

条件必须是 `bool`。无 `else` 的 `if` 只允许出现在语句语境，结果为 `void/none`；值语境必须有 `else`，各可达分支必须完全同型，不自动提升。

```nova
if ready {
    run();
}

let value = if ok {
    1
} else {
    0
};
```

`match` 按书写顺序执行第一个为真的分支。单值模式按 `==` 比较；比较表达式和逻辑表达式按原表达式判断，不重排范围具体性。

- 语句语境允许省略 `else`；无匹配时为 `void/none`。
- 值语境必须有 `else` 覆盖无匹配路径；分支结果必须完全同型。
- 值模式与比较模式**不可在同一 `match` 体内混用**（第二章 2.8.3 / D-21：一个 `match` 只表达一种分派意图）。
- 不引入类型模式、解构模式和隐式范围模式。

`eqroot.nova` 的 `match d { d > 0 => ... }` 因而是按顺序执行的条件分支集合。

### 3.3.4 数值转换和运算

隐式转换只有 `char → int → float`；`bool` 不参与数值转换。

| 表达式类别 | 规则 |
|---|---|
| `char` 算术 | 必须先显式转为 `int`；结果按 `int` 计算 |
| `int` 与 `float` | `int` 提升为 `float`，结果为 `float` |
| 其他混合算术 | 取提升链上的最窄公共类型 |
| 数值比较 | 先按同一提升规则转换，再比较 |
| `bool` | 只参与 `and`、`or`、`xor`、`not` |

显式转换写作 `T(expr)`：

- `float → int` 向零截断，NaN、无穷或越界 trap；
- `int → char` 只接受 0–127；
- `float → char` 先向零截断为 `int`，再检查 0–127；
- 常量表达式中的非法转换直接编译错误。

32 位有符号 `int` 溢出、整数除零、整数商溢出和 `range` 零步长均 trap。整数除法向零截断，余数与被除数同号。

### 3.3.5 比较

- `float` 使用 IEEE 754：NaN 参与 `==` 得 `false`，参与 `<>` 得 `true`，参与 `<`、`>`、`<=`、`>=` 均得 `false`；正负零相等，无穷按顺序比较。
- `string` 只支持按内容比较的 `==` 和 `<>`，不支持排序运算。
- 用户自定义类和数组只支持按对象句柄身份比较的 `==` 和 `<>`。
- 不支持 `!=` 和运算符重载。

### 3.3.6 循环和跳转

`while` 和 `for` 是语句，不产生块值；条件必须是 `bool`。

```nova
for i in range(0, n, 1) {
    if stop(i) {
        break;
    }
    continue;
}
```

- `range(stop)`、`range(start, stop)`、`range(start, stop, step)`；终点不包含；支持负步长；零步长 trap。
- `for` 可迭代数组、字符串和字符串切片；循环变量按值取得元素。
- `break` 跳出最近的**循环**；`continue` 只作用于最近的循环。二者均不跳出 `match`（2026-09-24 按第二章 2.8.4 统一：`match` 分支执行完自然结束，"break 跳出 match"无可观察效果，且会破坏"break 只作用于循环"的单一模型；`match` 分支内的循环由该循环自身管理）。
- 不支持 `do-while`、`++`、`--` 和复合赋值。

## 实现约束

- AST 中区分 `ValueExpr`、`LValueExpr` 和 `VoidExpr`，避免把“可求值”误当成“可赋值”。
- 常量折叠阶段使用同一套转换和 trap 检查；编译期已知错误必须和运行时 trap 使用相同错误编号。
- `match` 不需要专门的模式匹配引擎，编译器可直接降级为有序条件链。
- 编辑器语法高亮只需把 `and/or/xor/not` 作为关键字运算符；`<>` 是唯一不等号。
