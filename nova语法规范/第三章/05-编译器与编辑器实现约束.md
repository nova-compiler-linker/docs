# 3.5 编译器、链接器与编辑器实现约束

本文件只记录第三章对工具链的最小要求，避免把实现细节散落在语义条款中。

## `nvc` 编译器

1. **词法和解析**：关键字、`<>`、`::`、`&T`、`const &T`、`&T const` 和 `array[T | n]` 必须有唯一解析路径。
2. **名字解析**：作用域树支持包、文件、函数、块四层；类成员在成员解析阶段加入候选集。
3. **类型检查**：所有表达式同时记录类型、值类别和写权限；`void` 表达式不能进入需要普通值的上下文。
4. **确定性初始化**：分支合流取“所有可达路径都已初始化”；循环出口保守按“可能零次执行”处理。
5. **重载解析**：候选排序只使用参数类型和固定提升链；产生唯一稳定的符号键。
6. **常量求值**：编译期和运行时共用转换、溢出、越界检查，避免同一表达式两种结果。
7. **诊断范围**：每个错误携带源文件、行列、主错误码和相关声明位置。

建议的最小错误码：

| 错误码 | 含义 |
|---|---|
| `NOVA-E-USE-BEFORE-INIT` | 读取可能未初始化的变量 |
| `NOVA-E-NOT-LVALUE` | 表达式不是稳定可写左值 |
| `NOVA-E-BORROW-LIFETIME` | 引用可能逃出来源对象生命周期 |
| `NOVA-E-OVERLOAD` | 无匹配或重载歧义 |
| `NOVA-E-TYPE` | 类型不匹配或非法转换 |
| `NOVA-E-RETURN` | 返回类型或返回路径不满足规则 |
| `NOVA-E-RUNTIME-BOUND` | 可在编译期确定的边界错误 |

## `nvld` 链接器

- 只处理编译器生成的已修饰符号；不参与表达式类型检查。
- 函数符号至少包含包名、文件名、函数名和参数类型列表。
- 类方法符号额外包含类限定名；覆盖方法保持自己的最终符号并记录虚调用关系。
- 句柄、引用和返回值的 ABI 必须在同一目标平台内一致；跨平台二进制兼容由目标三元组区分。

## 编辑器连接器

编辑器连接器只依赖稳定的语法树、符号表和诊断协议：

- 关键字和运算符表来自 `nova-spec.md`，本章不再引入编辑器专用语法；
- 补全按当前作用域和成员可见性过滤；
- 悬停显示类型、值类别和写权限，例如“`const &array`：只读引用”；
- 诊断使用上表错误码，不把运行时 trap 伪装成语法错误；
- `match`、`if`、`range` 等结构提供成对括号和分支模板，不自动生成未确认的语义糖；
- 代码格式化保持多目标赋值的左到右书写顺序和 `array[T | n]` 类型形状。
