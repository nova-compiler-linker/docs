# 3.1 声明、作用域与初始化

## 结论

### 3.1.1 声明

```nova
let a: int = 0;
let b = 0.0;
let c: int;
const limit: int = 10;
type Count = int;
```

- `let` 必须有类型标注或初始化器；`let x;` 非法。
- `let x = expr` 只从 `expr` 推导类型，绑定建立后类型固定。
- `let x: T = expr` 允许 `char → int → float` 的既定提升；其他情况要求同型。
- `const` 只限制当前绑定再次赋值，不等同于编译期常量，也不自动改变其他别名的写权限。
- `type A = B` 是纯类型别名；`A` 和 `B` 的类型、表示、对齐和 ABI 等价。

### 3.1.2 作用域、遮蔽和前向引用

作用域从外到内为：包、文件、函数、块。查找名字时优先使用最近的可见绑定。

```nova
let x = 1;
{
    let x = 2;  # 只遮蔽块内的 x
    print(x);
}
print(x);
```

- 允许嵌套块遮蔽外层变量和参数。
- 同一块中后出现的 `let` 创建新绑定；已经解析的表达式仍指向原绑定。
- 局部变量不能前向引用；顶层函数、类和类型别名可以前向引用。
- 初始化器不能直接或间接读取正在初始化的变量。
- 类和类型别名不能重复定义；函数重复声明按重载签名检查。

### 3.1.3 包级声明

模块顶层**只允许 `const`**，不存在包级可变 `let`（2026-09-24 按跨章节协调 S-18 修订——本节原称「包级变量」，与「顶层无可变状态 ⇒ 无模块初始化函数 ⇒ 循环 import 安全」的设计前提冲突；第四章 §7.1 [3]、第二章 2.5.4/2.9.3 一致）。

`const` 的初值只允许编译期可求值的常量表达式：

- 不得调用运行时函数；
- 不得读取运行时状态；
- 不得依赖初始化顺序；
- 跨文件常量依赖必须形成无环图。

包级常量在链接前完成求值，不能生成运行时初始化函数。

### 3.1.4 确定性初始化

`let x: T;` 可以省略初始化器，但每条可能到达读取点的路径都必须已写入 `x`。编译器使用路径敏感的数据流分析：

- `if` 的所有可达分支都写入，分支后才算已初始化；
- `while` 和 `for` 可能执行零次，循环体内的写入不能证明循环后已初始化；
- `return`、`break`、`continue` 终止的路径不继续参与分析；
- 读取前无法证明已初始化时，编译期报错。

示例中的输出参数是语言内建的初始化写操作：

```nova
function main() -> int {
    let n: int;
    input(n);       # input 写入 n，并向确定性初始化分析报告“已初始化”
    println("{}", n);
    return 0;
}
```

`input` 只能接受可写稳定左值。标准库的字符串格式化方法也可以把一个未初始化的 `string` 槽位作为输出目标；完成格式化后该变量才可读取。这一条用于兼容 `point.nova` 的 `let s: string; s.format(...); return s;`。

## 示例依据

- `hanoi.nova` 先声明 `n: int`，再用 `input(n)` 写入后传给递归函数。
- `point.nova` 先声明字符串槽位，再由 `format` 写入后返回。
- `inherit.nova` 的成员 `name` 在构造函数中赋值后使用。

## 实现约束

### `nvc`

1. 解析器为每个声明创建唯一符号 ID，避免遮蔽时只按字符串查找。
2. 类型检查阶段建立四状态数据流：`未声明`、`未初始化`、`已初始化`、`不可继续`。
3. `input` 和字符串 `format` 作为带写集合的内建函数登记在标准库接口中。
4. 诊断至少区分：`NOVA-E-USE-BEFORE-INIT`、`NOVA-E-UNKNOWN-NAME`、`NOVA-E-REDECLARATION`。

### `nvld` 与编辑器连接器

- 包级常量只输出只读符号，不输出运行时初始化段。
- 编辑器补全按作用域树返回最近绑定，并保留遮蔽关系。
- “可能未初始化”诊断附带读取位置，便于跳转到声明和最近的赋值路径。
