# 3.4 函数、数组与运行时边界

## 结论

### 3.4.1 函数声明和返回

```nova
function gcd(a: int, b: int) -> int { ... }
function log(message: string) { ... }       # 由返回语句推导 void
```

- 函数参数按位置匹配；不支持默认参数和关键字参数。
- 普通用户函数参数固定；标准库格式化 I/O 可以接受异类型可变尾参数。
- 省略返回类型时，从所有带值 `return` 推导；所有带值返回必须同型；没有带值返回时为 `void`。
- `void` 函数允许 `return;` 和 `return none;`。
- 非 `void` 函数的每条可达路径都必须返回值；返回值的类型须与返回类型相同，或沿提升链**加宽**到返回类型（`int` 可返回给 `float`，S-29；收窄须显式转换）；到达函数末尾视为编译错误。

### 3.4.2 重载和继承查找

普通函数和成员函数都可以重载。参数类型列表参与区分，返回类型不参与。

调用解析顺序（2026-09-24 按统一裁决 S-26 修订步骤 2–3：成员函数查找采**遮蔽制**，与第四章 6.4 [3]、6.6 [8] 一致——原"沿继承链收集全部候选"与第四章"派生类同名遮蔽基类重载集"矛盾）：

1. 按名字和实参数量筛选；
2. 成员调用在**静态类型及其继承链上自派生向基类逐层找同名成员集**：命中的**第一个**声明了该名字的同名成员函数集合即为候选集，**更基类的同名重载集被遮蔽**（要调用被遮蔽版本须显式 `super.名字(...)`，第四章 6.6 [8]）；
3. 普通（非成员）函数在本包/模块作用域解析，不涉及继承；
4. 精确匹配优先于 `char → int → float` 的提升（提升次数更少者优先）；
5. 只有唯一最佳候选时调用合法，否则报告无匹配或歧义（`NOVA-E-OVERLOAD`）。

`override` 要求派生类存在同签名基类方法；同签名覆盖基类候选，不产生两个可选目标。函数名不是一等值，不支持匿名函数、lambda 和闭包。

### 3.4.3 数组

```nova
let a: array[int | 9] = [9, 3, 7, 5, 1, 8, 6, 4, 2];
```

- 数组是定长类型，长度写在类型中；不支持动态数组。
- `array[T | n1, n2, ...]` 的每个维度都是编译期正整数；运行时按行主序连续存储。
- `length()` 返回所有维度元素总数；多维下标使用**逗号全维形式** `a[i, j]`，一次消费全部维度，返回元素引用；**不存在部分下标**——`a[i]` 对多维数组是编译错误，也不产生行视图（2026-09-24 统一裁决 C-1：原"单下标按行主序访问"与协调稿 `a[i][j]` 链式互斥，采逗号全维下标，与第二章 2.6.4.2 一致）。
- 数组字面量元素按共同提升类型推导；空数组必须有类型上下文；元素数量必须匹配声明长度。
- 数组没有隐式深拷贝；传参、返回和赋值复制数组句柄。
- 任一维下标小于零或不小于该维长度时 trap。

第三章只提供字符串切片；数组不自动产生切片类型，避免编辑器和类型推导出现第二套视图规则。

### 3.4.4 字符串

`string` 是内置句柄类型，逻辑上保存 UTF-8 字节序列和长度：

- `length()` 返回字节长度；
- `[index]` 返回元素引用，索引单位为字节（字符串不可变，该引用为只读）；
- `[n:m]` 是左闭右开视图，返回 `&string`，不复制底层缓冲；
- `==` 和 `<>` 按内容比较；
- 赋值和传参复制句柄；格式化方法 `format` 按**一次性初始化写入**工作——只写未初始化槽位或空串，不改变已有内容（字符串不可变，协调稿 S-08、第二章 2.6.4.1）。

这套规则覆盖 `point.nova` 的格式化返回和 `inherit.nova` 的 `&string const` 参数，同时保持实现只需要一个句柄结构。

### 3.4.5 入口和运行时 trap

程序入口的合法签名只有以下两种形态（协调稿 S-05；第二章 2.8.7、第四章 §8.2 [11] 与 §8.8 一致；`async` 入口由运行时启动调度器并等待其任务完成后，再取其返回值作退出码）：

```nova
function main() -> int { ... }
async function main() -> int { ... }
```

返回值即进程退出码（Nova 层为完整 `int`；进程启动器在系统边界取 `result mod 256` 作为可观察退出码，与协调稿 S-05 一致）。运行时 trap 立即终止当前程序并返回非零退出码，不提供异常捕获和隐式清理。

以下情况统一 trap：数组或字符串越界、除零、整数溢出、浮点转换越界、`range` 步长为零、悬垂引用和栈耗尽。

### 3.4.6 运算符优先级

从高到低固定为（2026-09-24 按统一裁决 B-8 调整：关系与相等拆为两级，与第二章 2.4.8 一致——对合法程序两者解析结果无差，取 C/C++/Rust 传统的两级表以免将来堵路）：

1. 调用、下标、成员访问、切片；
2. 一元 `+`、一元 `-`、`not`；
3. `*`、`/`、`%`；
4. `+`、`-`；
5. `<`、`>`、`<=`、`>=`；
6. `==`、`<>`；
7. `and`；
8. `xor`；
9. `or`；
10. 赋值和多目标赋值。

同一层级左结合；赋值不参与普通表达式嵌套，禁止级联赋值。

## 实现约束

- `nvc` 的函数符号键为“限定名 + 参数类型列表”；返回类型不进入符号键。
- `nvld` 只解析已完成名字修饰的符号，不重新执行重载决议。
- 数组和字符串句柄布局必须在 ABI 中固定；本章不要求链接器理解元素类型，只要求调用约定一致。
- 运行时 trap 使用统一入口 `nova_trap(code, source_span)`；编辑器把错误码映射为稳定诊断。
